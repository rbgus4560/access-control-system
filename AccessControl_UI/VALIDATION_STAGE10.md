# 10-1단계 실시간 서버 영상 10.1 — 2026-10-18

## 구현 범위

- 인증 앱에서 이미 수신하는 실시간 카메라 JPEG를 서버로 전달한다. 서버에서 USB 카메라를 다시 열지 않는다.
- 기본 상태·권한 TCP 5050, 영상 TCP 5051. 영상 포트는 사용자가 입력한 상태 포트 + 1이며 두 연결 모두 IPv4 루프백 전용이다.
- 최대 초당 5프레임, 최신 프레임 하나만 보관한다. 영상 통신과 얼굴 인증 TCP는 별도 작업이며 영상은 출입 이벤트를 생성하지 않는다.
- 1.5초가 지난 영상은 표시하지 않는다. 카메라 종료 시 빈 프레임을 보내고 서버 이미지를 지운다. 서버 중지·재시작 후 영상도 자동 재접속한다.
- JPEG 400,000바이트, 전체 패킷 540,000바이트 제한. 서버는 이미지 가로·세로 1280 이하를 확인하고 최대 표시 폭 640으로 디코딩한다.
- 서버 영상은 원본 카메라 화면이다. 얼굴 Mesh/판정 표시를 영상 자체에 합성하지 않는다. 출입 판정은 오른쪽에 별도로 표시한다.

## 내부 검증 완료

- .NET 8.0.426 MSBuild: FaceRecognition, FaceEnrollment, AccessControlServer 세 프로젝트 빌드 성공.
- 기존 NetworkChecks: 얼굴 비교 상태·오래된 분석 차단·TCP ACK·재접속·32개 권한 조합·저장된 GRANTED 응답 검사 통과.
- VideoChecks: 패킷 왕복, 크기·메타데이터·JPEG 마커 검증, 오래되거나 미래 시각인 영상 숨김, 포트 범위, 소스 만료 검사 통과.
- 실제 루프백 TCP: 영상 전송, 카메라 종료 통지, 서버 재시작 자동 재접속, 연결 종료 이미지 해제 통과.
- 잘못된 영상 패킷 이후 다음 연결 수락, 불완전 패킷 도중 종료 취소, 영상 서버가 꺼진 상태에서도 권한 채널 ACK 유지 통과.

영상 전송 테스트의 바이트는 전송 검사용이며 실제 JPEG 디코딩 검증은 아니다. Linux에서는 Windows WPF 실행과 사용자 카메라를 확인할 수 없다. 다음 PC 확인 전에는 실제 화면 출력과 성능까지 검증했다고 주장하지 않는다.

## 사용자 PC 확인 순서

1. 기존 세 앱 종료 후 ZIP의 AccessControl_UI 내용을 기존 폴더에 함께 덮어쓴다. DB 재생성·얼굴 재등록 불필요.
2. Start_Stage10.cmd 실행. 서버와 인증 앱 제목에 10.1 확인.
3. 서버 DB 연결 및 목록 조회, TCP 서버 시작(5050). 영상 5051도 함께 준비된다.
4. 인증 앱에서 서버 연결(5050), 등록 직원 조회, 기존 직원 얼굴 불러오기.
5. 카메라·AI 연결. 서버의 큰 영상 영역에서 움직임 확인. 영상은 얼굴 보정·비교가 준비되기 전에도 나올 수 있다.
6. 정면 보정·얼굴 비교 켜기 후 서버 영상과 별도로 GRANTED/DENIED 및 DB 기록 확인.
7. 인증 앱 카메라 연결 종료 시 서버 영상이 사라지는지 확인. 카메라 재연결 후 복원 확인.
8. 서버 중지 후 TCP 서버 시작 시 인증 앱에서 다시 버튼을 누르지 않아도 영상·상태 재접속 확인. 서버 앱 전체 재실행 시 기존 규칙대로 DB 얼굴을 다시 불러온다.

## 미구현·후속 범위

10단계 전체 완료가 아니다. 녹화 파일 생성, 24시간 타임라인 실제 재생, 이벤트 시각 재생 및 클립 추출은 아직 연결하지 않았다. 선택 직원 한 명과의 1:1 얼굴 비교, 실제 문 구동 미연결, 위조 얼굴 방지 미구현 등 기존 한계도 남아 있다. 2대 카메라 동시 실행·두 번째 모니터 배치는 사용자 환경에서 별도 확인이 필요하다.
