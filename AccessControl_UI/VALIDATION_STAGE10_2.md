# 10-2단계 카메라 구간 녹화 10.2 — 2026-10-18

## 동작과 보관 위치

- 인증 앱에서 카메라·AI를 연결하면 자동 녹화 시작. 등록 앱 카메라는 녹화하지 않는다.
- 이미 열려 있는 동일 카메라의 프레임을 복사해 별도 스레드의 OpenCV VideoWriter(mp4v)로 기록한다. 추가 카메라나 외부 ffmpeg.exe 설치는 필요 없다.
- 640폭 기준 카메라 화면, 고정 10fps, 최대 60초(600프레임) MP4 구간. 카메라 정상 종료 시 짧은 마지막 구간도 마무리한다.
- 파일 위치: `%LOCALAPPDATA%\AccessControlSystem\recordings\CAM-01\YYYYMMDD\구간ID.mp4`. 날짜 폴더는 UTC 기준이며 DB 조회 화면의 시각은 Windows 현지 시각이다.
- 동일 구간ID의 JSON 파일은 동기화·복구용 정보다. MP4와 JSON을 함께 보관한다. 얼굴 특징이나 DB 비밀번호를 녹화 정보에 넣지 않는다.
- 카메라 프레임이 0.5초 이상 없으면 구간을 닫는다. 짧은 프레임 간격은 가장 최근 프레임으로 채우며 장시간 단절을 정상 녹화로 늘리지 않는다. 녹화 지연 시에도 새 구간으로 나누므로 실제 빈 구간이 생길 수 있다.
- 구간 종료 후 첫 프레임 디코딩 및 프레임 수를 확인한 파일만 READY로 표시한다. 이는 모든 프레임 무결성 검사를 뜻하지 않는다.

## DB 동기화와 상태

- 기존 access_control.recording_segments 테이블을 사용한다. 새 DDL이나 DB 초기화는 없다.
- RECORDING: 시작된 구간. READY: 파일 마무리와 확인 완료. FAILED: 인코딩·복구 실패 구간.
- 매 3초 동기화 주기에서 최대 16개 정보 파일을 서버의 기존 사용자 전용 로컬 파이프로 전송한다. 영상 본문은 DB에 넣지 않는다.
- 같은 구간ID의 재전송은 중복 행을 만들지 않으며 RECORDING을 완료 상태로 갱신한다. 완료 상태를 과거 RECORDING 요청으로 되돌리지 않는다.
- 서버/DB 미연결 중 파일·JSON은 계속 저장한다. 재실행 시에도 남은 정보를 재전송한다. 서버 DB 연결을 다시 만들면 확인 캐시를 비우고 현재 DB에 재동기화한다.
- 서버는 허용한 로컬 녹화 경로·카메라·시각·길이·프레임 수, 실제 JSON과 요청의 일치, READY 파일 실제 크기를 확인한다. Windows 파일 읽기는 원자적 교체를 허용하는 공유 모드로 수행한다.
- 서버의 '서버 중지'는 영상·상태 TCP 중지다. 로컬 파이프와 DB가 켜져 있으면 녹화 정보 동기화는 계속될 수 있다.
- 인증 앱 왼쪽에서 녹화 상태·DB 동기화 대기 건수 확인 및 녹화 폴더 열기. 서버 '녹화 구간 조회'에서 최근 500건 조회. 조회 창은 자동 갱신이 아니므로 버튼을 다시 누른다.

## 오류와 복구

- 같은 녹화 폴더에 단일 기록자 잠금을 사용한다. 이미 녹화 중인 인증 앱이 있으면 새 기록자를 시작하지 않는다.
- 비정상 종료한 MP4는 다음 카메라 연결 시 읽어 볼 수 있는 경우만 READY로 복구한다. MP4 헤더가 마무리되지 않아 읽을 수 없으면 FAILED로 표시하며 파일을 임의 삭제하지 않는다.
- 저장 장치의 여유 공간이 20GB 미만이면 새 녹화 구간 시작을 중단하고 오류를 표시한다. 카메라 영상과 얼굴 인증은 별도로 계속될 수 있다.
- **3일 보관·오래된 파일 자동 삭제는 아직 구현하지 않았다.** 이번 단계는 녹화·구간 메타데이터 동기화다. 파일 자동 정리 정책은 후속 연결 대상이다.

## 내부 검사

- Python 구문 검사: segment_recorder.py, wpf_bridge.py 통과.
- 주입한 테스트 인코더로 8개 로직 검사 통과: 짧은 구간 종료, 분할·유일ID·프레임 상한·구간 시간 비중첩, 카메라 중단 시 구간 종료·재개, 무응답 인코더 실패, 최신 프레임 큐, 단일 기록자 잠금, 읽기 가능 여부에 따른 복구, 여유 공간 중단.
- 세 WPF 프로젝트 .NET 8 빌드 통과.
- FaceChecks: 기존 5방향 특징·로컬 요청 검사 및 녹화 경로·상태·시간/프레임 수·동기화 직렬화 검사 통과.
- NetworkChecks: 기존 권한 정책·실제 상태 TCP·영상 TCP·재접속·영상 장애 시 인증 통신 유지 검사 통과.
- 이 환경에서는 테스트 프로젝트 MSBuild 시작 시 호스트 ProcessName 오류가 발생해, 동일 .NET SDK의 Roslyn 컴파일러와 .NET 8 참조 어셈블리로 검사 프로젝트를 컴파일하고 실행했다. 실제 세 WPF 프로젝트는 솔루션 MSBuild로 빌드했다.

테스트 인코더는 실제 MP4 파일을 만드는 OpenCV가 아니다. 개발 환경에는 cv2 및 Windows WPF 실행 환경, 실제 PostgreSQL 서버가 없어 실제 코덱·카메라 파일·새 DB INSERT는 사용자 PC에서 확인해야 한다. 위 내부 검사만으로 실제 녹화 재생과 DB 저장을 확인했다고 주장하지 않는다.

## 사용자 PC 확인 순서

1. 기존 세 앱 종료 후 새 ZIP 내용을 기존 폴더에 덮어쓰기. Start_Stage10.cmd 실행. 서버·인증 앱 제목의 10.2 확인.
2. 서버 DB 연결 및 목록 조회, TCP 서버 시작. 인증 앱 서버 연결 및 카메라·AI 연결. 녹화 상태가 '녹화 중'인지 확인.
3. 10~15초간 카메라 앞에서 움직인 후 인증 앱 카메라 연결 종료. 몇 초 후 동기화 대기 0건 확인.
4. 서버 녹화 구간 조회. 최신 구간이 READY, 종료시각·파일 크기가 있는지 확인.
5. READY 행 선택 후 선택 구간 폴더 열기. 해당 MP4를 기본 플레이어로 열어 영상이 실제로 재생되는지 확인. JSON은 동기화 정보이며 재생 파일은 MP4다.
6. 카메라를 다시 연결해 70초 이상 유지. 새 60초 READY 구간과 진행 중 RECORDING 구간, 카메라 종료 후 마지막 READY 확인.
7. 서버 앱 종료 중에도 인증 앱 카메라 유지. 다시 서버 실행·DB 연결 후 대기 구간이 동기화되는지 확인.
8. 기본 인증은 기존처럼 DB 직원 얼굴 불러오기·정면 보정·얼굴 비교 켜기로 확인한다.
