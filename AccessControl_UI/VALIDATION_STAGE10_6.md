# 10.6 원본 녹화 72시간 보관 정리

## 적용과 첫 확인

1. 세 앱 종료 후 ZIP의 AccessControl_UI 안 내용을 기존 폴더에 덮어쓴다.
2. Start_Net10.cmd 실행. 인증·서버 창 제목 10.6 / .NET 10 확인.
3. 인증 앱 왼쪽 원본 보관 72시간 상태 확인. 기본 시작 시 1회, 이후 정상 루프에서 약 1분마다 정리한다.
4. 서버 DB 연결 후 기존 녹화 구간 조회. 최근 원본이 READY로 남아 있는지 확인.
5. Run_Retention_Checks.cmd 실행. 임시 파일 검사 PASS를 확인한다. 실제 원본·클립·DB는 검사 대상이 아니다.

현재 사용자의 원본은 10월 18~19일 자료이므로 만료 0건은 정상일 수 있다. 기능 확인을 위해 PC 날짜를 바꾸거나 실제 원본 JSON 시각을 조작하지 않는다.

## 정책

- 최근 3일을 달력 날짜가 아닌 **구간 종료 시각부터 72시간**으로 정의한다.
- 알려진 CAM-01 원본 경로·UTC 날짜·GUID·프레임 수·기간·크기를 검증한 READY 원본만 새 삭제 대상으로 삼는다.
- RECORDING·FAILED·메타데이터 없는 파일·지정 위치 밖·링크 경로는 자동 삭제하지 않는다.
- 앱 내부에서 재생 중인 원본과 추출 작업의 전체 원본 목록은 사용 보호를 걸고 정리를 미룬다.
- 외부 재생기의 Windows 파일 점유 등으로 삭제가 실패하면 확인 필요 상태로 남기고 다음 주기에 재시도한다.
- 별도 clips 폴더는 정리하지 않는다. 클립 자체의 보관·수동 삭제 UI는 이번 기능 범위가 아니다.
- 공간이 20GiB 미만이라고 최근 72시간 파일을 임의로 더 삭제하지 않는다. 기존 새 녹화 공간 확인 기준을 유지한다.
- 인증 앱이 실행 중일 때 정리한다. 서버가 꺼졌더라도 원본 정리는 가능하고 DB 반영은 재연결 후 진행한다.
- 한 번에 최대 64개를 삭제하고 잔여 후보는 다음 주기로 넘긴다.

## 파일과 DB 일관성

1. 로컬 JSON을 DELETING으로 원자적 저장한다. 아직 DB DELETED로 보내지 않는다.
2. 원본 MP4를 삭제한다. 실패하면 진행 정보를 보관한다.
3. 실제 MP4가 없음을 확인한 후 DELETED·DeletedAt·DeletionReason을 JSON에 저장한다.
4. 기존 RecordingSync가 삭제 기록을 재전송한다.
5. 서버가 동일 JSON과 실제 파일 부재를 확인하고 기존 recording_segments의 status·deleted_at·deletion_reason에 반영한다.

JSON과 DB 행은 삭제하지 않는다. 삭제 전 크기·시작/종료·경로를 이력으로 유지한다. DB 연결 실패 때 JSON이 outbox 역할을 한다. 삭제 도중 종료됐으면 DELETING 정보를 다음 실행에서 재처리한다. 이미 삭제된 DB 행을 READY로 되돌리는 상태 전이는 허용하지 않는다.

기존 스키마의 deleted_at·deletion_reason 컬럼을 사용하므로 새 생성 SQL은 없다. 서버 녹화 목록에 삭제 시각·사유 열을 표시한다. Database/12_verify_retention.sql은 읽기 전용 확인용이다.

## 내부 확인 2026-10-19

- .NET SDK 10.0.402 Windows 대상 세 WPF 빌드 성공.
- RetentionChecks: 종료 시각 72시간 경계·최근 파일·녹화 중 파일 제외, 실제 임시 파일 삭제·JSON 완료 상태·멱등 재실행 통과.
- 재생/추출용 사용 보호와 해제 후 재처리 통과.
- 삭제 의도 기록 후 종료, 파일 삭제 후 완료 기록 전 종료의 복구 검사 통과.
- 경로 위조·크기 변경·심볼릭 링크 제외 통과.
- 삭제 메타데이터 요청/응답 계약 전달 검사 통과.
- 기존 FaceChecks·NetworkChecks 통과. 실제 loopback TCP·영상 재접속 검사 포함.

임시 검사 파일은 영상 디코딩용 파일이 아니라 파일 수명주기를 확인하기 위한 바이트 파일이다. 원본 정리 검사는 코덱 성능·얼굴 인식 정확도 검사와 다르다. 실제 사용자 녹화 파일이나 실제 DB의 DELETED 갱신은 내부 검사에서 수행하지 않았다. 사용자 Windows의 실제 UI 표시·파일 점유·DB 삭제 상태 전이는 별도 확인이 필요하다.
