# 12.3 전체 직원 자동 식별(1:N)

12.2.4의 자동 보정과 12.2.3의 UI·녹화·클립 수정 사항을 포함한다. 인증할 직원을 선택하는 화면을 제거했다. 얼굴 특징 모델·전처리·512차원 임베딩·거리 기준은 유지하고, 검색 대상을 한 명에서 전체 등록 직원으로 변경했다.

## 적용

1. 서버·클라이언트·등록 앱을 모두 종료한다. 정상 동작하는 12.2.4 폴더는 백업한다.
2. 이번 압축 파일을 새 폴더에 푼다. 서버와 클라이언트를 **둘 다** 이번 버전으로 실행한다. 기존 DB와 AppData, 모델 캐시를 삭제하지 않는다.
3. `Start_Server.cmd`, `Start_Client.cmd`를 실행하고 창 제목 **12.3**을 확인한다.
4. 클라이언트 설정의 `카메라·AI`에서 **AI 폴더를 이번 압축 파일의 FaceAI**로 지정한다. Python 가상환경·모델 캐시는 기존 경로를 유지한다. 이전 FaceAI 폴더로 실행하면 새 모듈이 필요하다는 안내가 나온다.
5. 서버 DB 연결 및 TCP 서버 시작 후 클라이언트를 연결한다.
6. 클라이언트가 등록 직원 전체를 자동 동기화한다. 카메라·AI를 연결하고 정면을 잠깐 유지하면 자동 보정 후 비교를 시작한다. 직원 선택은 필요 없다.

**추가 SQL·테이블·Python 패키지 설치는 필요 없다.** 기존 등록 5방향·9방향·연속 등록 대표 샘플을 모두 사용한다. 카메라는 등록 앱과 인증 앱 중 한 곳에서만 연다.

## 역할과 처리

- 서버: 호환되는 활성 얼굴 등록 목록 제공, 특징 복호화 및 TLS 전송, 후보 직원의 현재 활성 상태·출입 권한·장치 상태 재확인, 최종 허가/거부와 출입 기록 저장.
- 클라이언트: 메모리에서 전체 직원 기준 관리, 얼굴 특징을 분석 프레임당 한 번 추출, 모든 직원의 샘플과 코사인 거리 비교, 직원별 최소 거리로 순위 계산.
- 같은 직원의 서로 다른 자세 샘플은 한 사람으로 묶는다. 자세 샘플 두 개가 비슷하다는 이유로 모호 판정을 하지 않는다.
- 1위 거리 0.450 이하이고 2위와의 차이가 0.050 이상이면 일치 후보다. 후보는 서버의 권한 확인을 통과해야 허가된다.
- 가장 가까운 직원도 0.450을 초과하면 미등록/불일치로 처리한다. 미등록자를 가장 가까운 직원의 이름으로 기록하지 않는다.
- 1위가 기준 이내여도 2위와의 거리 차이가 0.050 미만이면 **식별 보류**다. 이 결과로 허가 기록을 만들지 않는다. 후보 점수 차이는 클라이언트와 서버 모두에서 확인한다.
- 비활성 직원과 출입 권한이 없는 직원도 호환되는 활성 얼굴 등록이 있으면 비교 대상에 포함한다. 얼굴을 식별한 뒤 서버가 비활성/권한 없음으로 거부한다.
- 얼굴 미등록자·비활성 얼굴 등록·다른 모델 버전 등록은 비교 대상이 아니다. 기준이 하나도 없으면 인증하지 않고 서버에서 얼굴을 등록하도록 안내한다.

## 자동 동기화

- 기본 10초 주기로 서버 등록 목록을 확인한다. 새 직원·재등록·직원 이름/상태 변경·얼굴 등록 해제·서버 재시작을 반영한다.
- 변경 없는 얼굴 특징은 다시 다운로드하지 않는다. 서버 재시작/DB 재연결로 세션이 바뀌면 기준과 서버 발급 식별 토큰을 다시 받는다.
- 얼굴 기준은 직원별 작은 메시지로 전송한다. 전체 수신과 검증이 끝나야 새 목록을 한 번에 적용한다. Python도 전체 메시지 적용 완료를 응답한다.
- 도중에 등록 목록이 바뀌거나 어떤 직원의 특징이 손상되면 일부만 적용하지 않고 인증을 보류한 채 재시도한다.
- 통신 실패 시 과거 기준으로 새 허가를 내리지 않도록 클라이언트 인증 결과를 차단한다. 로컬 녹화·기존 재연결/메타데이터 동기화는 별도로 유지한다.
- 기준은 C#과 Python 메모리에만 유지하며 추가 얼굴 특징 파일을 저장하지 않는다.
- 현재 데모의 명시적 상한은 1000명이다. 초과 시 일부를 조용히 생략하지 않고 동기화 실패로 보류한다. 1000명 처리 성능을 측정하거나 보장한 것은 아니다.

## 수동 중지와 재연결

- `얼굴 비교 중지`를 누르면 직원 목록이 갱신되어도 중지 상태를 유지한다. `얼굴 비교 시작`으로 재개한다.
- 카메라를 다시 연결하면 최신 직원 기준을 다시 적용하고 자동 시작한다.
- 동일 미등록자의 최근접 직원이 분석마다 바뀌어도, 그 이유만으로 새로운 인증 시도를 만들지 않도록 처리했다.

## 실제 PC 확인 순서

1. 서버에 서로 다른 사람 A·B의 얼굴이 각각 등록돼 있는지 확인한다.
2. 클라이언트 하단에 동기화된 직원 수가 표시되는지 확인한다.
3. A·B가 번갈아 카메라를 바라보고, 직원 선택 없이 이름이 바뀌는지 확인한다.
4. 서버 출입 기록의 직원 정보와 허가/거부가 실제 상태와 일치하는지 확인한다.
5. B의 출입 권한을 끄고 B를 다시 인증한다. 얼굴은 식별하되 서버가 거부해야 한다.
6. 미등록자를 비추면 불일치여야 한다. 동일 얼굴을 서로 다른 직원에게 중복 등록했다면 점수가 비슷해져 식별 보류가 나오는 것이 정상이다.
7. 등록을 추가/교체한 뒤 다음 동기화에 자동 반영되는지 확인한다. 실제 반영 시간은 네트워크와 AI 처리 시간만큼 늘어날 수 있다.
8. 비교를 수동 중지한 상태에서 목록이 갱신되어도 다시 켜지지 않는지 확인한다.

## 자동 검사와 한계

- Python 검사 49개: 기존 등록·자동 시작·녹화·클립 검사와 전체 직원 검색·모호 판정·원자적 기준 교체 검사 포함.
- 실제 C# AiClient와 Python worker 연결(카메라/얼굴 모델만 합성 대역): 단계별 적용 ACK, A/B 자동 식별, 등록 제거 후 불일치, 모호 판정, 목록 갱신 중 수동 중지 유지, 빈 목록, 카메라 프로세스 재시작 후 재적용.
- C# 동기화 검사: 등록 변경/삭제·변경 없는 특징 재사용·서버 세션 변경·손상/도중 변경된 목록 거부·빠른 재연결·빈 목록 처리.
- TLS 실제 소켓: catalog/gallery-load 신규 요청, 기존 인증·영상·클립 전송·서버 재시작 복구 검사.
- 실제 catalog SQL은 격리된 PostgreSQL WASM 엔진에서 검사했다. 실제 학교 DB 연결은 사용자 PC에서 확인해야 한다.
- 세 WPF 앱 교차 빌드 통과. Windows 실화면·실제 USB 카메라와 여러 사람의 정확도·처리 속도는 이번 환경에서 측정하지 않았다. 모호 판정의 거리 차이 0.050은 실제 환경 평가가 필요한 초기 설정값이다.
- 두 PC 네트워크 연결, 아래 방향 등록 감지, 과거 동기화 15건의 실제 해소 여부는 기존 확인 과제로 남아 있다.
