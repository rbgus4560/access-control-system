# 12.1 역할별 UI 정리

이번 변경은 이미 나눈 서버·클라이언트 역할에 맞춘 화면 정리다. .NET 10·WPF-UI 4.3.0을 유지한다. 두 PC 통신 프로토콜, 얼굴 모델/샘플 선택, DB SQL, 녹화·클립 전송 알고리즘은 12.0과 같다. 추가 SQL은 없다. 기존 15번을 아직 적용하지 않았다면 최초 두 PC 기능 검증 전에 적용한다.

## 화면 구성

| 화면 | 메인에 보이는 내용 | 메뉴에서 여는 창 |
|---|---|---|
| 관리 서버 | 큰 관제 영상, 현재 서버 판정, 수신 상태, 최근 출입 기록 5건 | 직원·권한, 얼굴 등록, 전체 출입 기록, 타임라인·클립, 녹화 구간, 서버 설정 |
| 구역 클라이언트 | 큰 카메라, 서버 최종 판정, 불러온 얼굴 기준, 실제 카메라/서버 상태, 이번 실행의 최근 인증 | 인증 기준 선택(읽기 전용), 클라이언트 설정, 최근 인증 상세 |
| 서버 얼굴 등록 | 직원 선택, 연속 등록 안내·진행률, 카메라, 선택 직원 DB 저장 | 카메라·AI 실행 설정은 접힌 상태에서 필요할 때 펼침 |

- 서버 `서버 설정`은 DB·관리자 / 클라이언트 연결 / 등록 장치 탭으로 나눈다. 기존 실제 컨트롤을 이동했으며 창을 닫아도 DB 서비스·TCP 수신을 중지하지 않는다.
- `출입 기록` 별도 창은 기존 DB 최근 500건 목록이다. 조회·기록 선택·영상 열기 기능을 유지한다. 메인에는 같은 실제 목록 중 최신 5건만 표시한다.
- 서버 메인 최근 기록은 선택하면 상세 창을 연다. 전체 출입 기록에서는 상세 버튼이나 기록 영상 기능을 사용한다.
- 클라이언트의 최근 인증은 서버가 DB 기록 완료로 응답한 이번 실행의 최대 10건이다. 선택하면 이름·사원번호·판정·사유·거리·이벤트 ID를 별도 창에서 확인한다. 전체 과거 기록과 영상은 서버에서 조회한다.
- 직원 정보 수정·신규 직원·얼굴 등록·권한 변경은 서버 메뉴에 있다. 클라이언트는 비교할 한 명의 얼굴 기준만 불러온다.
- 등록 화면의 진행률·선별 안내는 기존 AI 상태를 그대로 표시한다. 화면을 정리했다고 아래로 숙일 때의 검출이나 인식 정확도를 개선한 것은 아니다.
- 서버 상단의 DB 상태는 마지막 연결 설정 여부다. 실시간 DB heartbeat 상태를 새로 측정하는 표시가 아니다. 클라이언트 연결 표시는 기존 최근 ACK/프레임 신선도 기준을 유지한다.

## 지금 한 PC에서 확인할 순서

1. 실행 중인 앱을 모두 닫고 기존 정상 폴더를 보존한다. 이번 ZIP은 새 폴더에 압축 해제한다.
2. 학교 서버 PC에서 `Start_Server.cmd` 실행. 제목의 12.1 확인.
3. 왼쪽 `서버 설정`을 열고 DB·관리자 탭에서 기존 DB 연결과 관리자 선택. 닫았다 다시 열어도 설정 컨트롤과 상태가 유지되는지 확인.
4. 관제 메인의 최근 기록과 `출입 기록` 별도 창을 확인. 기록 선택 시 상세 창이 열리고, 전체 기록 창의 조회가 동작하는지 확인.
5. 직원·권한, 얼굴 등록, 녹화 구간, 타임라인 메뉴가 각각 별도 창으로 열리는지 확인. 새 직원/얼굴을 만들 필요는 없고 먼저 화면 배치부터 확인한다.
6. `Start_Client.cmd`는 다른 PC가 없어도 화면 확인용으로 열 수 있다. 카메라를 등록 앱과 동시에 점유하지 않도록 둘 중 하나만 연결한다. 서버 연결/얼굴 조회까지 같은 PC에서 검사하려면 LAN 주소의 도달 여부와 키를 맞춰야 하며 이 절차가 내일의 두 PC 검증을 대신하지 않는다.

서버에 새 클라이언트가 연결되지 않은 동안 카메라·판정이 대기로 보이는 것은 정상이다. 새 폴더의 FaceAI 경로와 현재 PC의 Python/모델 설정도 확인한다. 연결 코드에 비밀 키가 들어 있으므로 코드가 보이는 화면을 공유하지 않는다.

## 구현 확인

- 세 WPF 앱을 .NET 10 SDK 10.0.402에서 교차 빌드 성공. XAML 이름·이벤트 핸들러·공유 상세 창 참조를 컴파일 검사했다.
- 설정/기록 창은 닫힐 때 실제 뷰의 부모 연결을 해제해 동일 컨트롤로 다시 열도록 구현했다. 데이터 수신과 녹화 작업의 수명은 기존 메인 앱에 유지했다.
- 새 상세 창은 실제 DB 행 또는 서버 ACK에 포함된 값만 표시한다. 미리 채운 샘플 인물·허가 결과·가짜 연결 상태를 넣지 않았다.
- Windows에서의 실제 화면 배치·창 재열기·USB 카메라 표시 확인은 아직 남아 있다. 두 PC 통신·영상·판정·녹화·클립 현장 검증은 내일 DEPLOY_TWO_PC.md 순서로 진행한다.
