# 10-4 출입 기록 시각 재생 10.4 — 2026-10-18

## 동작

- 서버 출입 기록 행을 더블클릭하거나 선택 후 '선택 기록 영상' 버튼을 누르면 인증 앱으로 재생 요청을 보낸다.
- 화면의 초 단위 문자열을 해석하지 않고, 이벤트 ID로 DB의 원본 event_time을 다시 조회해 밀리초 이하 시각을 보존한다.
- 같은 Windows 사용자 전용 로컬 Named Pipe를 사용한다. 이벤트 ID·카메라·UTC 시각·표시 설명만 전달하며 파일 경로·권한 명령·얼굴 특징은 전달하지 않는다.
- 인증 앱에서 이벤트 날짜의 로컬 READY 구간을 찾고 해당 위치에서 재생. PLAYBACK 제목에 과거 기록의 직원·결과·사유를 함께 표시한다. 이는 현재 출입 허가 표시가 아니다.
- 해당 시각에 READY 파일이 없으면 녹화 없음 안내. RECORDING 구간은 완료된 뒤 다시 요청해야 한다. 가까운 다른 영상으로 바꿔 성공했다고 표시하지 않는다.
- 재생 요청 처리 중 사용자가 LIVE 또는 다른 시각으로 이동하면 이전 비동기 요청이 뒤늦게 화면을 덮지 않도록 요청 순서를 확인한다.
- 카메라를 새로 열거나 얼굴을 재등록하지 않고 기존 녹화와 DB 출입 이력으로 확인할 수 있다.

## 내부 확인

- 세 WPF 프로젝트 .NET 8.0.426 솔루션 빌드 성공.
- FaceChecks: 기존 얼굴·녹화·타임라인 검사 및 이벤트 재생 ID·카메라·시각 누락/지연/미래·요청 크기·한글 원본 시각 직렬화 검사 통과.
- NetworkChecks: 기존 권한·상태 TCP·영상 TCP·재접속·영상 연결 실패 시 인증 유지 검사 통과.
- 실제 DB 이벤트 조회 쿼리와 Windows 사용자 전용 재생 파이프·WPF 전환은 사용자 PC에서 확인해야 한다. 메모리 직렬화 검사를 실제 IPC 검증으로 주장하지 않는다.
- 서버의 'PLAYBACK 화면 확인' 응답은 요청 처리·파일 열기를 시작했다는 뜻이다. 실제 디코딩 성공은 인증 앱의 영상으로 확인한다.

## 적용 및 사용자 확인

1. 기존 앱 종료 후 새 ZIP 덮어쓰기, Start_Stage10.cmd 실행. 두 앱 10.4 확인.
2. 서버 DB 연결 및 목록 조회. 기존 출입 기록에서 녹화 범위 안의 기록 선택. 예: 2026-10-18 15:49:07은 15:48:58.402~15:49:38.802 녹화 안에 있다.
3. '선택 기록 영상'을 누르고 인증 앱 PLAYBACK에서 해당 시각 영상과 기록 설명 확인.
4. LIVE 복귀, 같은 기록 더블클릭으로 다시 재생 확인.
5. 녹화가 없는 시각의 기록은 녹화 없음 안내와 이전 영상 해제를 확인.
6. 10-3에서 별도로 요청한 직접 시각 재생·LIVE 복귀, 카메라 인증·녹화 유지 확인도 함께 진행.
