# 10.8 · 안내형 움직임 수집과 대표 샘플 자동 선택

## 적용 순서

1. 현재 앱들의 카메라 연결을 종료하고 서버·인증·등록 앱을 닫는다. 정상 동작한 기존 폴더를 보관하고 ZIP의 AccessControl_UI 내용을 기존 폴더에 덮어쓴다.
2. DBeaver의 기존 access_control_system 연결에서 Database/14_enable_guided_samples.sql 전체 실행. 기존 데이터는 유지하며 sample_no 허용 범위와 UNIQUE 제약을 확장한다. 이미 적용한 13번 SQL은 다시 실행할 필요 없다. 초기 생성 SQL도 실행하지 않는다.
3. Start_Net10.cmd 실행. 창 제목 10.8 확인, 서버 DB 연결·기존 관리자 선택·TCP 시작.
4. 기존 기준 불러오기는 그대로 가능하다. 등록할 때 인증 카메라 연결을 종료하고 등록 창의 직원 조회·선택·카메라 연결을 진행한다.

## 사용

- 정면을 바라본 상태에서 회전 등록 시작 클릭. 시작 프레임을 정면 기준으로 보정한다. 정면 보정 버튼을 따로 누를 필요 없다. 시작할 때 이미 고개를 돌리고 있으면 잘못된 기준이 되므로 취소 후 정면에서 다시 시작한다.
- 정면 다음 왼쪽·오른쪽·위·아래 안내를 따른다. 천천히 돌리거나 들고 숙였다가 정면으로 돌아온다. 각 방향에서 멈추거나 촬영 버튼을 누를 필요는 없다.
- 각도 변화가 너무 작거나 프레임이 흐리면 진행되지 않을 수 있다. 안내된 방향으로 조금 더 천천히 움직인다. 기존 좌우·상하 반전 설정도 유지한다.
- 정면 1개와 좌우·상하 각각 다른 각도 2개, 총 9개의 대표 특징이 선택되면 완료한다. 대각선 칸을 별도로 채우지 않는다. 복합 회전도 주된 회전 방향의 후보로 사용할 수 있으나 네 대각선 각각의 확보를 보증하는 방식은 아니다.
- DB 저장은 선택한 직원 확인 후 사용자가 누른다. 등록 취소/미완성 상태는 기존 완성 기준을 교체하지 않는다. 새 등록을 DB에 저장하면 이전 활성 등록은 이력으로 보존한다.
- 등록 카메라 종료 후 인증 앱 DB 불러오기. 기준 9개, 본인·타인·얼굴 이탈·다중 얼굴 확인. 인증 앱 재시작 후 재촬영 없이 DB에서 다시 불러온다.

## 자동 선별 기준

- 얼굴 1명, 검출·눈 정렬·최소 얼굴 크기·Laplacian 선명도 35 이상이라는 기존 품질 조건을 통과한 프레임만 사용한다.
- 약 0.45초 이상 간격으로 후보를 검토한다. 이미 확보한 시점과 약 3도 이내로 비슷하고 선명도 개선도 없으면 임베딩 계산을 생략한다. 모든 카메라 프레임을 저장하지 않는다.
- 각 방향 후보를 최대 8개씩 메모리에 유지한다. 서로 다른 각도(주 회전축 차이 7도 이상)와 선명도 점수를 함께 고려해 두 대표를 선택한다. 최소 자세 범위는 좌우 18도, 상하 14도다. 과도한 회전(pitch 32도, yaw 38도 초과)·옆 기울임(roll 12도 초과)은 제외한다.
- 정면 특징과 코사인 거리 0.60을 넘는 후보는 제외한다. 이는 등록 품질 조건으로, 동일인·위조 방지를 보증하지 않는다. 출입 비교 임계값은 기존 0.450을 유지한다.
- 새 기능은 정지 3회/0.6초 조건을 요구하지 않는다. 실제 모델 처리 속도와 카메라 선명도에 따라 사용자의 움직임 속도 조정이 필요하다.
- 기존 5방향·10.7의 9방향은 그대로 복원한다. 새 형식은 FRONT와 LEFT/RIGHT/UP/DOWN 각각 sample_no 1·2를 저장한다. 전송 키의 #2는 두 번째 샘플이라는 의미다. 대각선 이름으로 다른 방향 사진을 위장하지 않는다.
- 원본 후보 사진이나 영상을 등록용 파일로 저장하지 않는다. 선택된 ArcFace 512차원 특징만 기존 DPAPI 방식으로 암호화해 DB에 저장한다. 기존 인증 영상 녹화 기능은 별도로 동작한다.
- dlib·MediaPipe·ArcFace 모델과 전처리는 그대로다. 모델 재학습은 하지 않는다. 샘플 선택 방식 변경이 인식 정확도 향상을 입증하는 것은 아니므로 본인·타인 검증을 별도로 수행한다.

## 내부 검증

- Python 전체 39개 검사 통과. 신규 6개는 움직임만으로 완료·프레임 품질/중복·메모리 상한·복합 회전·기존 계약·실제 워커 자동 보정/수집/내보내기/취소를 검사한다. 카메라 모델 대신 가짜 분석 엔진을 사용한다.
- C# 특징/파이프 계약·DB pose/sample 번호 복원·크기 제한 왕복·TCP·영상·보관 정리 검사 통과.
- 세 WPF 프로젝트를 Linux의 .NET 10 SDK에서 교차 빌드한다. 실제 Windows 화면·DPAPI·카메라 동작을 대신하지 않는다.
- 별도 임시 PostgreSQL 엔진(PGlite)에 원본 등록 테이블 DDL과 13·14 마이그레이션을 적용했다. 기존 5/9개 보존, 신규 9행 저장/키 복원, 중복/범위/방향 제약 거절, 반복 적용, DDL 실패 롤백을 확인했다. 사용자의 실제 DB에 접속해 실행한 검증은 아니다.

## 사용자 PC에서 남은 확인

14번 SQL 정상 반영, 안내 방향·움직임 속도·진행률, 완료 후 DB 9행 저장, 기존/신규 기준 복원과 재시작, 본인/타인 판정. 이 결과가 확인되면 WPF UI 라이브러리로 최종 화면을 정리한다.
