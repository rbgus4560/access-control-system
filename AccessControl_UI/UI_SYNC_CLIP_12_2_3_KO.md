# 12.2.3 적용 및 확인

## 적용

1. 서버·클라이언트·얼굴 등록 앱을 모두 종료한다.
2. 기존 정상 소스 폴더를 백업하고 이번 ZIP을 새 폴더에 푼다. 기존 DB와 AppData 폴더는 삭제하지 않는다.
3. 새 폴더의 `Start_Server.cmd`, `Start_Client.cmd`를 실행한다. 창 제목의 **12.2.3**을 확인한다. 이전 바로가기나 이전 bin 폴더로 실행하지 않는다.
4. 등록 화면 설정·진단과 클라이언트 설정의 AI 폴더를 **이번 압축 파일의 FaceAI**로 지정한다. 기존 Python 가상환경과 모델 캐시 경로는 그대로 사용할 수 있다.
5. 같은 학교 PC에서 서버 DB 연결·TCP 서버 시작 후 클라이언트를 연결한다. 카메라는 등록 또는 인증 중 한 앱에서만 연다.

이번 수정에 추가 DDL 실행은 필요 없다. 이미 적용한 `client_metadata` 칼럼을 사용한다.

## UI 수정

- LIVE CAMERA 제목과 등록 안내문을 별도 세로 행에 배치한다(12.2.2 수정 포함).
- 오른쪽 등록 패널에 세로 스크롤바 공간과 내용 여백을 확보한다.
- 서버·클라이언트·등록 앱의 표 머리글을 단색으로 통일한다. Windows 기본 그라데이션을 제거하고 정렬·열 너비 조정은 유지한다.
- 클립 폴더 버튼은 창 하단에 고정한다(12.2.2 수정 포함).

## 녹화 동기화 수정

기존 DB 구간이 서버의 정해진 로컬 원본 경로를 사용하고 새 동기화는 `client://CAM-01/<구간ID>`를 사용하면, 같은 구간이어도 경로 비교에서 충돌할 수 있었다.

새 UPSERT는 구간 ID·카메라·시작 시각·허용된 상태 전이가 일치하고 **기존 경로가 현재 서버의 정규 원본 경로인 경우에만** 원격 위치로 전환한다. 임의 경로·다른 시작 시각·완료 상태 역행은 거부한다. 실패한 한 구간이 신규 구간을 막지 않는 기존 처리는 유지한다.

학교 PC의 과거 대기 15건이 모두 이 경로 충돌인지는 아직 확정되지 않았다. 실행 후 `DB 녹화 동기화 · 대기 0건`인지 확인한다. 남는 항목은 구간 ID와 오류 로그로 확인하며, 파일·JSON·DB 행을 일괄 삭제하지 않는다.

서버 로그: `%LOCALAPPDATA%\AccessControlSystem\server-api-errors.log`

## 클립 실패·복구 수정

- 원본을 채울 수 없는 요청은 클라이언트가 실패 확정으로 응답한다. 서버는 FAILED 메타데이터와 사유를 저장하고 DB 반영 성공 후 해당 remotejob만 정리한다.
- 통신·저장 공간·Python 실행 오류는 재시도 가능 상태로 보존한다. 이전 버전 클라이언트는 실패 확정 응답을 보내지 않으므로 서버와 클라이언트를 함께 갱신한다.
- 서버 재시작 후 READY뿐 아니라 FAILED 결과도 DB 반영을 재시도한다.
- 서버 보관 MP4는 `clips`에, 클라이언트 임시 MP4는 `clips\client_temp`에 저장한다. 한 PC에서도 전송 확인 후 임시 파일 정리가 서버 사본에 영향을 주지 않는다.
- 이전 인코딩 실패로 남은 불완전 파일은 해당 클라이언트 임시 파일만 정리하고 재시도한다.
- 실패 사유는 `clips\<구간이 아닌 클립ID>.mp4.error.txt`에 남긴다. FAILED는 성공한 클립이 아니며, 범위를 다시 선택해 새 요청을 만든다.

## 검증 범위

- .NET 10 WPF 앱 3개 교차 빌드 통과.
- 실제 TLS 소켓 테스트: 인증·영상 연결/재접속, 분리된 프로세스의 영상·클립 전송, 해시 검증, DB 실패 후 재시도, 오래된 요청 FAILED 정리, 불완전 임시 클립 복구, 한 PC의 서버 사본 보존.
- 동기화 회귀 검사: 실패 20건 중 신규 구간 처리, 실패 복구, ACK 중복 방지.
- 생산 UPSERT를 격리된 PostgreSQL WASM 엔진에서 실행: 정규 경로 전환·멱등성·시각/경로/상태 불일치 거부·삭제 전이. 실제 학교 DB와 Npgsql 연결 검사는 별도다.
- OpenCV 실제 합성 MP4 검사 4개: 구간 결합·프레임/해시 확인·잘못된 원본 거부·클라이언트 임시 출력과 기존 서버 사본 분리.
- Windows 화면 배율별 배치와 학교 PC의 실제 과거 15건·이전 클립 요청은 적용 후 확인해야 한다. 두 PC 네트워크와 아래 방향 등록 감지 개선은 이번 범위에 포함하지 않는다.
