# 얼굴 AI 검증 v3 — dlib 검출 최적화

기존 WPF 프로젝트·DB와 별도로 실행하는 검증 프로그램입니다.
최종 제품은 등록·인증·서버 3개 WPF 프로그램이며, 이 코드는 그 안에 연결할 Python AI 기능의 확인용입니다.


## 수정본 적용 (기존 설치 완료한 경우)

1. 기존 카메라 창을 Q로 종료합니다.
2. ZIP 안의 `face_ai_python` 폴더 내용을 기존 같은 폴더에 덮어씁니다. 새 파일 `ai_worker.py`와 `dlib_fast.py`도 함께 있어야 합니다.
3. **가상환경 재설치·모델 재다운로드는 필요하지 않습니다.** 기존 `model_cache` 폴더를 그대로 두세요.
4. 기존 폴더에서 실행합니다.

```bat
conda activate access_face_ai
python face_check.py --camera 0
```

좌우·상하 방향 부호 옵션을 사용했다면 같은 옵션을 다시 붙입니다.
종료 전 등록 특징은 메모리에만 있었으므로 새 실행에서 정면 보정·5방향 등록은 다시 해야 합니다.

## v3 dlib 최적화

기존 DeepFace dlib 경로는 정렬용 검은 여백을 먼저 붙인 큰 영상에서, HOG의 추가 확대(upsample=1)를 사용해 검출했습니다.
v3 기본 `fast` 모드는 **최대 가로 480픽셀의 축소·그레이 영상에서 확대 없이(upsample=0) HOG 검출**을 수행합니다.
좌표를 원본 크기로 복원한 뒤 **원본 영상에서 5점 랜드마크와 눈 기반 정렬**을 처리합니다.
검출을 마친 뒤 회전용 여백을 붙이므로, HOG는 큰 여백 영상을 훑지 않습니다.
DeepFace 0.0.93이 로딩한 같은 dlib 모델·5점 모델과 정렬 함수를 사용하며, 모델 교체나 재학습을 하지 않습니다.

- `dlib detail`: 검출 시간, 원본 영상 정렬 시간, 실제 검출 영상 가로 크기를 추가로 표시합니다.
- 새 실행 창과 첫 줄에 `v3` / `dlib (fast)`가 나오는지 확인하세요.
- 검출 영역·정렬 결과가 조금 달라질 수 있습니다. 정면 보정과 5방향 등록·본인/타인 비교를 새로 확인해야 합니다.
- 작거나 먼 얼굴·옆얼굴에서는 확대 검출보다 놓치는 경우가 생길 수 있습니다. 검출되지 않은 얼굴을 임의로 인식하지 않습니다.
- 새 패키지를 설치할 필요 없이 기존 환경과 모델을 사용합니다.

기본 실행:

```bat
python face_check.py --camera 0
```

얼굴 검출이 잘 안 되면 가로 640픽셀 검출로 확인합니다 (확대는 계속 0):

```bat
python face_check.py --camera 0 --detector-width 640
```

동일 조건에서 기존 방식의 시간·검출 결과를 비교하려면:

```bat
python face_check.py --camera 0 --detector-mode standard
```

같은 카메라·해상도·조명·거리·정면 자세에서 몇 차례 관찰하세요.
한 장의 테스트 이미지에서 얻은 속도 개선 비율은 실제 카메라나 모든 얼굴 조건의 보장값이 아닙니다.
추론 속도와 함께 다섯 방향의 검출·본인/타인 점수를 확인한 뒤 WPF에 연결합니다.
현재 등록 특징은 종료 시 사라지며 DB에 저장하지 않습니다.

### v2에서 분리한 화면과 처리 구조

- **왼쪽 LIVE CAMERA**: 현재 카메라 영상. 얼굴 마킹·인식 결과를 덧씌우지 않습니다.
- **오른쪽 LAST ANALYZED FRAME**: 마지막으로 분석한 프레임과 메시·얼굴 박스. AI가 느리면 이쪽만 천천히 갱신됩니다.
- 비교 점수·자세는 **오른쪽 분석 프레임에만 해당**합니다. 왼쪽의 현재 사람에 대한 즉시 판정이 아닙니다.
- `analyzed frame age`: 분석한 영상이 촬영된 후 경과한 시간입니다. 2.5초를 넘으면 비교 점수를 숨깁니다.
- `UI fps`: 실제 영상 표시 루프의 갱신 빈도, `AI output fps`: AI 결과의 최근 출력 간격 기준 빈도입니다.
- `mesh / dlib+align / ArcFace / total`: 단계별 경과 시간(ms). `--`는 해당 단계 미실행입니다.
- mesh 시간에는 RGB 변환과 MediaPipe 실행이 포함됩니다. dlib+align은 선택한 모드의 검출·랜드마크·눈 정렬 전체 경과 시간입니다.
- total은 분석 시작부터 명령·비교 처리까지이며 큐 대기·그리기·카메라 입력·화면 출력은 제외합니다. 단계 합계와 정확히 같지는 않습니다.
- 여러 얼굴 검출 시 `MULTIPLE FACES - ONE PERSON AT A TIME` 안내와 얼굴별 박스를 표시하고 비교를 중단합니다.
- 영문 대문자·소문자 키를 모두 받습니다. 키를 한 번 누른 뒤 명령 반영 안내를 기다리세요.
- 키를 누른 시점보다 **나중에 촬영한 프레임**에서 보정·등록을 수행합니다. 처리 중에도 해당 자세를 유지해 주세요.
- UI는 AI와 다른 **프로세스**에서 실행합니다. AI는 하나의 프로세스에서 모델·등록 상태를 순서대로 다룹니다.
- 대기 영상은 최대 1개만 유지하고 최신 영상으로 바꿉니다. 밀린 영상을 차례로 분석하지 않습니다.
- 이 변경은 영상 표시의 AI 대기를 분리한 것입니다. **AI 추론 자체의 속도 향상을 보장하지 않습니다.**
- 기본 AI 입력 제출 상한은 5fps이며 실제 처리 속도는 아닙니다. 필요 시 `--ai-fps 3`으로 상한을 낮출 수 있습니다.

## 사용하는 기술

| 역할 | 사용 기술 | 실습과 연결 |
|---|---|---|
| 카메라 입력·영상 처리 | Python OpenCV | `vision AI 실습_0911`의 cv2 |
| 얼굴 검출 | DeepFace가 로딩한 dlib HOG 모델 (기본: 축소 검출) | 실습 7페이지의 dlib 얼굴 검출 |
| 얼굴 정렬 | 같은 dlib 5점 모델과 DeepFace 눈 위치 기반 정렬 함수 | 실습의 68점 모델과 파일·점 개수는 다름 |
| 얼굴 메시 | MediaPipe Tasks Face Landmarker | 이번에 추가: 다수의 얼굴 지점 추정 |
| 방향 계산 | 얼굴 변환 행렬에서 회전 추출·정면 기준 상대각 계산 | 이번에 추가: 정면·상하·좌우 판정 |
| 특징 추출 | DeepFace `represent`, ArcFace, 512차원 | 실습 DeepFace `analyze`에서 신원 인식 용도로 확장 |
| 비교 | L2 정규화 특징의 코사인 거리 | 작을수록 유사. 등록 5개 중 최소 거리 사용 |

SCRFD·YuNet·SFace·ONNX Runtime은 이 버전에서 사용하지 않습니다.
나이·성별·감정 분석과 졸음 감지 역시 현재 출입 통제 검증 범위에 포함하지 않습니다.

## 1. 설치 (Windows / Anaconda Prompt)

1. ZIP을 풀고 `face_ai_python` 폴더를 엽니다.
2. **Anaconda Prompt**를 열고 해당 폴더로 이동합니다. 예:

```bat
cd /d "C:\Users\사용자이름\Downloads\AccessControl_FaceAI_Python\face_ai_python"
setup_environment.bat
```

`access_face_ai`라는 별도 Conda 환경을 생성합니다. 기존 `vision_ai2`나 WPF 프로젝트에서 설치하지 않습니다.
이미 같은 이름의 환경이 있으면 삭제하지 말고, 아래 명령으로 먼저 활성화하여 설치 상태를 확인하세요.
Windows x64, Python 3.11, CPU 실행 기준입니다. GPU/CUDA 설정은 필요하지 않습니다.
시스템의 C++ 런타임 DLL 오류가 있으면 오류 문구를 확인하여 Microsoft Visual C++ Redistributable x64 설치 여부를 점검하세요.

## 2. 설치·모델 준비 확인

```bat
conda activate access_face_ai
python check_setup.py --prepare
```

처음 실행하면 **ArcFace 사전학습 가중치를 다운로드**하므로 인터넷 연결과 충분한 디스크 공간이 필요합니다.
TensorFlow 등 설치 패키지까지 포함하면 수 GB가 필요할 수 있습니다. 다운로드 중 창을 종료하지 마세요.
미리 학습된 모델을 사용하는 것이며, 새 모델을 학습시키는 과정은 아닙니다.
MediaPipe 모델과 dlib 5점 모델은 ZIP에 포함하고 SHA-256으로 확인합니다.
ArcFace 가중치는 DeepFace 0.0.93의 모델 로더를 사용해 내려받으며 별도로 고정 해시를 검증하지는 않습니다.
모델 파일만 이 폴더의 `model_cache`에 저장됩니다. 촬영 얼굴·특징은 저장하지 않습니다.

정상 완료 시 `Models loaded; blank frame rejected: PASS`가 나옵니다.
이것은 모델 로딩·빈 영상 거부 확인이며, 실제 사람의 인식 정확도 검증을 뜻하지 않습니다.
오류가 나면 다음 단계로 넘어가지 말고 오류 텍스트를 전달해 주세요.

## 3. 카메라 실행

```bat
python face_check.py --camera 0
```

다른 카메라 앱과 WPF 카메라 프로그램을 닫고 실행합니다.
카메라가 열리지 않으면 다음을 하나씩 시도하세요.

```bat
python face_check.py --camera 1
python face_check.py --camera 0 --backend msmf
```

카메라 번호는 USB 장치 번호와 같다고 보장되지 않습니다. 원하는 카메라 영상이 나오는지 확인하세요.
OpenCV 표시창이 선택된 상태에서 **영문 입력**으로 키를 누릅니다.

## 4. 방향부터 확인

1. 얼굴 한 명만 나오게 하고 밝은 곳에서 카메라를 봅니다.
2. 정면에서 `0`을 눌러 현재 자세를 정면 기준으로 설정합니다.
3. 천천히 위·아래·왼쪽·오른쪽을 바라보며 `Pose` 표시를 확인합니다.
4. 화면은 좌우 반전하지 않았습니다. LEFT/RIGHT는 촬영 당사자의 방향을 기준으로 확인합니다.

첫 실행에서 방향 부호는 반드시 사람이 확인해야 합니다. 카메라·행렬 좌표계에 따라 반대로 표시될 수 있습니다.
좌우가 반대로 나오면 Q로 종료한 뒤:

```bat
python face_check.py --camera 0 --yaw-sign -1
```

상하가 반대로 나오면:

```bat
python face_check.py --camera 0 --pitch-sign -1
```

둘 다 반대이면 옵션을 함께 넣습니다. 다시 실행할 때 정면에서 0을 누르세요.
기본 방향 기준은 정면 각도 ±12도, 상하 18~35도, 좌우 18~40도, 고개 기울어짐 ±12도입니다.
경계 구간·복합 회전·과도한 회전은 UNKNOWN으로 거부합니다.
0은 장치·사용자 기준 보정이므로, 다른 사람이 비교할 때도 먼저 정면 보정이 필요할 수 있습니다.
방향 보정은 신원 확인이나 위조 방지를 뜻하지 않습니다.

## 5. 5방향 등록·동일인 비교

| 키 | 동작 |
|---|---|
| `0` | 정면 기준 보정, 진행 중인 등록 취소, 비교 중지 |
| `E` | 새 5방향 등록 시작 |
| `Space` | 안내된 방향이 맞고 3프레임 이상·0.6초 이상 유지됐으면 특징 1개 추출 |
| `T` | 완성된 기준 얼굴과 현재 얼굴 비교 켜기·끄기 |
| `C` | 등록 특징·진행 상태·정면 기준 모두 메모리에서 제거 |
| `Q` | 카메라 해제 후 종료 |

등록 순서: **FRONT / UP / DOWN / LEFT / RIGHT**.
각 방향에서 얼굴을 잠깐 멈추고 Space를 한 번 누르세요. 너무 크게 돌리면 dlib이 놓칠 수 있습니다.
정면 특징과 다른 방향 특징의 거리가 0.60을 넘으면 등록을 거부합니다. 이 값도 초기 검증값이며 동일인 보장이 아닙니다.
다섯 개가 모두 모였을 때만 새 기준을 활성화합니다. 중간 등록 실패·취소 시 기존 완성 기준은 유지합니다.
`E`를 다시 누르면 현재 미완료 등록부터 새로 시작합니다.

등록 완료 후 T를 누르면 AI가 유효한 새 프레임을 처리할 때 특징을 추출해 비교합니다.
먼저 등록한 본인을 확인하고, 그 다음 동의한 다른 사람이 카메라 앞에서 결과를 확인하세요.
표시는 `MATCH CANDIDATE` 또는 `NO MATCH`입니다. **직원 식별·출입 허가 결과는 아닙니다.**
직원 DB·권한 판정·TCP는 아직 연결하지 않았습니다. 등록 기준도 한 사람만 메모리에 유지합니다.
이 프로그램은 사진·영상 재생에 대한 위조 방지(liveness)를 구현하지 않습니다.

코사인 거리 기준값 **0.45는 이 검증을 위한 임시 값**입니다. 정확도 측정 결과나 공식 보장값이 아닙니다.
허용 각도·조명·본인/타인 데이터로 점수 분포를 측정한 다음 정해야 합니다.
설정 예: `python face_check.py --camera 0 --distance-threshold 0.40`.
검출 실패·여러 얼굴·메시 불일치·흐림·모델 오류·UNKNOWN 자세에서는 비교 결과를 표시하지 않습니다.
표시되는 비교 결과는 오른쪽 분석 프레임의 결과입니다. 촬영 후 2.5초를 넘긴 결과는 숨깁니다. 왼쪽 실시간 영상의 매 프레임 신원 판정은 아닙니다.
단계별 시간·프레임 나이는 위 화면 설명을 참고하세요.

## 알려진 한계와 다음 단계

- 영상 표시와 AI는 별도 프로세스입니다. AI 결과는 영상보다 늦게 갱신될 수 있으며, 실제 Windows UI FPS는 다시 확인해야 합니다.
- dlib은 측면에서 검출 실패할 수 있습니다. 적당한 각도에서도 실패하면 백엔드 변경을 근거와 함께 검토합니다.
- 얼굴 크기 100픽셀, Laplacian 분산 35 등의 품질 기준도 환경에 맞춰 조정해야 합니다.
- MediaPipe 메시가 한 명이고 dlib 검출도 한 명이며, 메시의 코 좌표가 dlib 얼굴 안에 있어야 진행합니다.
- 좌표계 방향·카메라 드라이버·인식 성능은 실제 Windows PC에서 검증해야 합니다.
- 다음 연결: AI 백그라운드 처리·C# 요청/응답, 등록 특징 DB 저장, 직원 조회·권한 판정·출입 기록.

## Npgsql / PostgreSQL / DBeaver

| 항목 | 역할 |
|---|---|
| PostgreSQL | 데이터 저장·조회·트랜잭션을 처리하는 DBMS |
| Npgsql | C#에서 PostgreSQL에 SQL을 보내고 결과를 받는 .NET 드라이버 |
| DBeaver | 사람이 테이블을 보고 SQL을 실행하는 DB 관리 도구 |

서버의 직원 저장 버튼은 C# 코드에서 Npgsql을 통해 PostgreSQL에 INSERT를 요청합니다.
이 Python 검증 프로그램은 DB에 접속하지 않습니다. 최종 DB 접근은 C# 서버에서만 수행합니다.

## 버전·배포 참고

핵심 패키지는 requirements.txt에 고정했습니다. Conda dlib과 일부 간접 의존성은 완전 잠금 파일이 아닙니다.
