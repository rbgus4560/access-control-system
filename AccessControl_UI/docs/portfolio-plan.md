# 포트폴리오 구성 초안

## 보여줄 역량

얼굴인식 AI를 WPF 클라이언트·관제 서버·PostgreSQL과 연결하고, 서버의 출입 권한 판정부터 기록·영상 조회까지 구현한 시스템 통합 역량.

AI 모델 자체 개발이나 정확도 개선 성과로 표현하지 않는다. 개발 기간, 팀 인원, 본인 담당 범위는 발표 자료 확정 전에 확인한다.

## PPT 흐름

| 장 | 내용 | 핵심 메시지와 필요한 증거 |
|---|---|---|
| 1 | 프로젝트 개요 | 목적, 사용 상황, 기술, 기간과 역할. 기간/역할은 확인 필요 |
| 2 | 전체 시스템 구성도 | 등록 앱·인증 클라이언트·관리 서버·DB의 책임과 데이터 흐름 |
| 3 | 핵심 기능: 얼굴 등록·직원 기준 동기화 | 등록한 얼굴 기준을 DB에 저장하고 인증에 반영하는 과정. 등록 화면과 짧은 시연 |
| 4 | 핵심 기능: 식별·서버 권한 판정 | AI 식별 결과를 서버에서 직원 활성/출입 권한과 대조해 최종 판정. 허가·거부 화면 |
| 5 | 핵심 기능: 관제·출입 기록·녹화 조회 | 실시간 영상에서 과거 기록/영상으로 이어지는 사용 흐름. 실제 화면과 재생 시연 |
| 6 | 문제 해결: 등록·인증 안정성 | 기존 트러블슈팅 문서에서 직접 설명 가능한 사례 하나를 골라 증상→원인→수정→검증으로 구성 |
| 7 | 문제 해결: 정보 삭제와 기록 보존 | 직원 정보·얼굴 특징 삭제와 출입 기록 FK 보존의 설계. 사용자 제공 DB 결과는 특징 0/활성 등록 0/기록 210건이며 개인정보를 가리고 사용 |
| 8 | 배운 점과 구조 정리 | 책임 분리, 공통 테마 통합, 실제 장치 검증과 자동 검사 범위의 구분. 소감보다 설계 판단을 설명 |

기존 합의한 네 부분인 개요→구성도→핵심 기능→문제 해결과 배운 점을 유지한다. 페이지 수는 발표 시간에 맞춰 조정한다.

## 사용할 증거와 표현 범위

- 실제 얼굴 등록→허가/거부→기록 조회→녹화 재생을 짧게 촬영한다. 허가 없는 타인의 얼굴과 직원 정보를 공개하지 않는다.
- 9분할 UI와 카메라 배치는 구현했으나 현재 실제 수신 구현은 CAM-01 한 대 기준이다.
- 리팩토링 후 앱 3종 빌드·자동 검사·합성 화면 검증은 통과했다. 실제 장치 흐름은 사용자가 그 이전에 확인한 결과와 구분한다.
- 30 FPS는 목표 설정이며 측정한 처리 속도로 쓰지 않는다. 얼굴인식 정확도 수치도 측정 근거 없이는 추가하지 않는다.
- 참고 문서: project-summary.md, troubleshooting.md, employee-deletion-ui-20261027.md, refactor-20261027.md.
