# 12.4 연결 자동화와 화면 개선

2026-10-22 변경. 얼굴 식별·권한 판정은 기존 12.3 흐름을 유지한다.

## 서버 시작

1. Start_Server.cmd로 빌드·실행한다. 서버 설정에서 DB 주소·DB명·사용자·비밀번호를 입력해 연결한다.
2. DB 조회에 성공하면 TCP 제어·영상·관리 서비스가 시작된다. 직원 관리는 연결된 서버 세션의 자격 증명으로 자동 조회하므로 비밀번호를 다시 입력하지 않는다. DB 연결을 바꾸거나 해제하면 기존 직원 창은 닫힌다.
3. 다음 실행에도 자동 연결하려면 서버 설정의 암호화 저장 선택란을 켜고 DB를 연결한다. 기본은 저장하지 않는다. 저장된 설정이 있으면 다음 시작에 DB 연결을 시도하고 성공 후 TCP를 시작한다.
4. TCP를 수동 중지한 뒤에는 DB 새로고침만으로 다시 시작하지 않는다. TCP 시작 버튼으로 재개한다. 포트 충돌·연결 실패는 화면 상태를 확인하고 수정 후 재시도한다.

저장 위치는 `%LOCALAPPDATA%\AccessControlSystem\server-startup.bin`이다. DB 비밀번호와 주소·TCP 포트를 Windows DPAPI CurrentUser로 암호화한다. 해당 Windows 계정의 자동 실행 편의를 위한 설정이며 다른 PC로 복사하는 배포 파일이 아니다. 체크를 해제하면 저장 파일을 지우지만 현재 세션은 유지한다. DB 연결 해제는 현재 세션을 해제하며, 저장 설정의 삭제와는 별개다. 비밀번호를 코드·문서·Git에 넣지 않는다.

## 클라이언트 시작

최초에는 서버의 연결 코드를 클라이언트에 적용한다. 저장한 연결 코드가 있으면 다음 실행 시 자동으로 연결을 시도한다. 코드 적용 직후에도 연결을 시작한다. 초기 페어링을 생략하거나 무인 재페어링하는 기능은 아니다. 서버가 꺼져 있거나 주소·방화벽·인증 문제가 있으면 상태를 보고 서버 연결 버튼으로 재시도한다.

카메라는 사용자가 직접 시작한다. 기존 동작대로 카메라 시작과 함께 로컬 구간 녹화도 시작되므로 시연 전에 보관 위치와 정책을 확인한다. 이번 변경은 카메라 자동 시작 기능을 추가하지 않는다.

## 화면 구성

서버 상단에 DB 준비·TCP·영상 상태를 분리했다. DB 표시는 마지막 연결 성공 세션 기준이며 지속적인 DB 건강 검사 결과가 아니다. 클라이언트에는 AI·직원 기준 수 상태를 표시한다. 등록 화면은 직원 선택 → 얼굴 수집 → DB 저장 순서를 안내한다. 직원 편집 영역은 작은 창에서 스크롤하고 저장 버튼은 하단에 고정한다. 세 앱 입력칸의 크기·간격을 통일했다.

실제 WPF 화면을 안전하게 확인하는 개발 옵션은 `--ui-preview --capture-output <절대 PNG 경로>`다. `--compact-preview`는 최소 창 크기, 서버의 `--employees-preview`·`--settings-preview`와 클라이언트의 `--settings-preview`는 보조 창을 선택한다. 미리보기에서는 운영 DB·카메라·통신을 시작하지 않는다. 일반 실행에는 이 옵션을 붙이지 않는다.
