# 실시간 영상 30 FPS 목표 조정 · 로컬 시험 · 2026-10-22

이번 README 업로드에는 문서만 포함되며, 아래 실행 코드 변경은 아직 GitHub에 반영하지 않았다.

사용자 보고: 인식보다 실시간 표시가 느리고 끊겨 보임. 코드 확인 결과 미리보기는 25 FPS, 서버 전송과 관제 화면은 약 5 FPS 상한이었다. 실측 병목이 모두 확인됐다는 의미는 아니다.

## 변경

- 카메라에 640×480, 30 FPS를 요청한다. 드라이버가 무시할 수 있으므로 보장값이 아니다.
- Python 실시간 JPEG 발행 목표를 25→30 FPS, WPF 미리보기 갱신을 40ms→약 33.3ms로 조정한다.
- 서버 영상 전송은 200ms 대기 대신 전송 시간을 포함한 약 33.3ms 간격을 사용한다. 전송이 느리면 추가 대기하지 않으며 최신 프레임 보관 구조를 유지한다.
- 서버 영상 갱신 타이머를 약 33.3ms로 분리한다. 대시보드/판정 상태 갱신은 기존 200ms로 유지한다.
- AI 분석 요청 0.2초(약 5 FPS), 녹화 0.1초(약 10 FPS), JPEG 품질 75와 해상도는 유지한다. 앞선 모든 카메라 표시 좌우 반전도 유지한다.

## 적용과 검증

서버·인증·등록 앱과 카메라 연결을 정상 종료한 뒤 다시 실행한다. 실행 중인 프로세스에는 변경이 소급 적용되지 않는다. 필요하면 Start_Server.cmd / Start_Client.cmd로 빌드한다. 등록 앱은 서버 메뉴에서 다시 실행한다.

솔루션 빌드(UseAppHost=false) 경고·오류 0, Python wpf_bridge.py 구문 검사 통과. NetworkChecks의 loopback 영상 전송·카메라 중지/재접속·신선도·제어 독립성 검사를 수행한다. 실제 웹캠 입력 FPS, 다른 PC에서의 표시 FPS·지연·CPU·대역폭은 미측정이다. 설정상 목표와 실측 성능을 구분한다.

원복은 wpf_bridge.py 미리보기 주기 1/25, FaceAiPanel 타이머 40ms, VideoClient 전송 후 대기 200ms 및 서버 RefreshVideo를 기존 monitorClock으로 돌리면 된다. 카메라 FPS 요청은 제거한다. 부하가 높다면 먼저 영상 목표를 15 FPS로 조정해 비교할 수 있다.
