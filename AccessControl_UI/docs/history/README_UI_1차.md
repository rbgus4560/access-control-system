# AccessControl WPF UI 1차

기존 인증 화면 참조를 유지한 UI 시연 프로젝트입니다. 모든 사용자·인증 이벤트는 샘플이며 실제 인증, 카메라, DB, TCP, 녹화 및 클립 생성은 연결되지 않았습니다.

## 실행
Windows + Visual Studio 2022(.NET 데스크톱 개발 워크로드) + .NET 8 SDK에서 `AccessControlSystem.sln`을 엽니다. 솔루션을 빌드한 뒤 각 프로젝트를 시작 프로젝트로 지정하여 실행하세요. .NET 8은 기존 초안의 임시 빌드 대상을 유지한 것이며 최종 버전 결정은 별도입니다.

명령줄에서는 이 폴더에서 다음을 실행합니다.

```powershell
dotnet build AccessControlSystem.sln
dotnet run --project AccessControlServer
dotnet run --project FaceRecognition
# 별도 터미널에서 실행
dotnet run --project FaceEnrollment
```

`dotnet run`은 창이 닫힐 때까지 유지되므로 프로그램마다 별도 터미널을 사용합니다. 인증 화면의 사용자 등록 버튼은 빌드된 형제 프로젝트의 등록 EXE를 찾아 별도 프로세스로 실행합니다. 배포 시에는 세 프로그램의 게시 결과를 한 폴더에 배치하세요. 중복 실행 방지는 후속 연결 단계입니다.

## 화면 확인 순서
1. 인증 메인: 시계 갱신, 타임라인 선택 시 PLAYBACK 표시, LIVE 복귀.
2. 사용자 목록: 이름·등록번호 검색, 활성·출입 권한 전환. 창을 닫으면 샘플 변경은 초기화됩니다.
3. 사용자 등록: 독립 FaceEnrollment 실행. 등록번호·이름 입력, 5방향 샘플 채택, 재촬영, 초기화, 완료 시연. 실제 촬영·품질 판단·특징 저장은 수행하지 않습니다.
4. 서버: 실시간 수신 영상 1채널 자리, 샘플 이벤트 추가와 선택 상세 보기. 다른 프로그램과 통신하지 않습니다.
5. 클립 추출: 날짜와 시간 구간 유효성 검사. 파일 생성 없음.
6. 설정: 확정한 3일·20GB·클립 수동 삭제 정책을 읽기 전용 표시.

## 이번 구현과 다음 작업
- 독립 WPF 프로젝트 3개, 사용자·설정·클립 보조 창 구성.
- 기존 인증 화면의 단일 카메라 영역과 24시간 타임라인 유지. 등록 화면 PIP 없음.
- 카메라 영역은 빈 자리이며 실제 사진이나 구현된 카메라 화면처럼 표시하지 않습니다.
- 등록 창은 현재 일반 대형 창입니다. 두 번째 모니터 자동 배치와 단일 인스턴스 전환은 후속 작업이며 현재는 직접 이동합니다.
- 타임라인은 선택 시각 표시까지 구현했습니다. 실제 녹화 구간·이벤트 마커·재생 연결은 후속 작업입니다.
- 로그인, 전체 사용자 편집, 서버 관리 팝업은 아직 구현하지 않았습니다.
- UI 확인 후 DB 항목 대조, PostgreSQL DDL, 서비스·통신 연결, 영상, AI 순서로 진행합니다.

## 검증 범위
제작 환경에 .NET SDK와 Windows WPF 런타임이 없어 컴파일 및 화면 실행을 검증하지 못했습니다. XML 구문과 XAML 이벤트 핸들러·클래스 연결, 솔루션 프로젝트 경로를 정적 검사했습니다. Windows에서 빌드·화면 확인이 필요합니다. UI_reference.png는 이전에 제공한 화면 기준 이미지입니다.
