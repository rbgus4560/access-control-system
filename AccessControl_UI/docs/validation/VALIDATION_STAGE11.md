# 10.7 · 회전·대각선 연속 얼굴 등록

## 적용

1. 기존 정상 버전 폴더를 보관한다. 서버·인증·등록 앱을 종료하고 ZIP의 AccessControl_UI 내용을 기존 폴더에 덮어쓴다.
2. DBeaver에서 기존 access_control_system 연결로 Database/13_enable_nine_pose_registration.sql 전체를 실행한다. 기존 face_templates의 pose CHECK만 확장한다. 기존 데이터·등록 이력은 삭제하지 않는다. 다른 초기 생성 SQL은 실행하지 않는다.
3. Start_Net10.cmd 실행. 서버 DB 연결 및 기존 관리자 선택, TCP 시작. 인증 앱에서 기존 5방향 기준 조회·불러오기를 먼저 확인한다.
4. 인증 카메라 연결을 끊고 등록 화면을 연다. 같은 USB 카메라를 두 앱에서 동시에 열지 않는다.

## 등록·저장·복원 확인

1. 직원 0511 등 실제 등록할 직원과 관리자를 확인한다. 등록 카메라 연결 후 정면 보정.
2. 회전 등록 시작 클릭. 정면을 먼저 유지한다. 이후 상·하·좌·우·대각선을 원하는 순서로 천천히 돌아본다. 각 방향은 약 1초 이상 잠시 유지한다. 별도 촬영 버튼은 필요 없다.
3. 안내 점이 초록색으로 채워지고 9방향 수집 완료가 나오는지 확인한다. 가운데 정면과 주변 8점이다. 고개를 과하게 돌리거나 옆으로 기울이지 않는다. 움직임 구간은 UNKNOWN일 수 있다.
4. 중간 등록 취소 시 이전 완성 기준이 유지되는지 확인한다. 미완성 6~8방향은 저장·인증 기준으로 허용하지 않는다.
5. 9방향 완료 후 선택 직원을 다시 확인하고 DB 저장 클릭. 새 활성 등록으로 전환되며 이전 등록은 비활성 이력으로 보존한다. 저장 실패 시 트랜잭션을 롤백한다.
6. 등록 카메라 종료, 인증 앱에서 DB 기준 불러오기. 기준 9방향 확인 후 정면 보정·비교 시작. 본인·다른 사람·얼굴 이탈·두 명을 확인한다.
7. 인증 앱을 재시작해 DB 9방향 재복원과 동일 동작을 확인한다. 대각선에서 비교가 가능한지 확인하되, 과도한 회전까지 일치를 보장하지 않는다.

## 구현

- dlib·MediaPipe·DeepFace/ArcFace 및 기존 전처리·512차원·코사인 거리 임계값 0.450을 유지한다.
- 얼굴 1명·유효 품질·자세 판정 및 독립 분석 3회/0.6초 이상 안정 조건을 만족한 미수집 방향만 자동 촬영한다. 너무 오래된 분석은 수집하지 않는다.
- 정면과 코사인 거리 0.60 이내인 샘플만 등록한다. 이는 등록 품질 필터이며 출입 인증 임계값이 아니다. 동일인임을 보증하는 위조 방지 기능도 아니다.
- 정면 첫 수집 이후 방향 순서는 자유다. 완성된 9개 특징을 한 번에 현재 기준으로 교체한다. 취소하면 기존 완성 기준은 유지한다.
- 상하 약 12~30도, 좌우 약 15~35도의 구역과 정면 중립 구역으로 9방향을 구분한다. roll 12도 초과는 거절한다. 부호 반전 설정은 기존 설정을 따른다.
- Python → WPF → 사용자 전용 파이프 → 서버 저장 → DPAPI → PostgreSQL → 복원 → TCP 출입 관찰까지 5/9방향을 지원한다. 기존 5방향은 재등록 없이 계속 사용한다.
- 대각선 기준이 추가돼도 인식 정확도 향상이 입증된 것은 아니다. 본인·타인 조건별 비교 결과를 별도로 기록한다.
- 녹화·보관·클립 기능은 10.6 동작을 유지한다. 이번 버전은 등록 안내용 표시를 추가했으며 최종 WPF UI 라이브러리 디자인은 다음 작업이다.

## 내부 검증과 실제 확인의 구분

.NET 10 SDK에서 세 WPF 프로젝트 빌드. Python 전체 33개 검사와 C# 특징/저장 계약·관찰/TCP/영상·원본 보관 검사를 수행한다. 자동 수집 테스트는 가짜 분석 엔진으로 실제 워커를 실행해 촬영 키 없이 9방향 수집·내보내기·취소를 검증한다.

실제 Windows 카메라·모델의 자세 범위, DPAPI/PostgreSQL의 9방향 저장·재시작 복원, 출입 판정은 위 사용자 PC 절차로 확인해야 한다. 내부 통과 결과만으로 해당 항목을 완료로 기록하지 않는다.
