# 12.4 Windows 검증 · 2026-10-22

환경: Windows, .NET SDK 10.0.401 / 런타임 10.0.12. 실데이터와 운영 자격 증명을 사용하지 않았다.

| 검사 | 결과와 범위 |
|---|---|
| AccessControlSystem.sln build --no-restore | PASS, 최종 경고 0·오류 0, 서버·인증·등록 |
| StartupChecks | PASS 6개: 설정 없음, 암호화 파일 평문 비노출, DPAPI 왕복, 덮어쓰기·임시파일, 손상 거부, 반복 삭제. 임시 폴더의 합성 비밀번호 사용 |
| TwoPcChecks --gallery-only | PASS, 갤러리 캐시·동기화·배치·재접속과 관찰·거부 정책 |
| NetworkChecks | PASS, 실제 loopback TCP·ACK·재접속·부분 프레임·정책·영상 경계/신선도·독립 제어·방향 호환 |
| WPF 미리보기 | PASS, 서버·직원·설정·인증·인증 설정·등록의 기본/최소 창 렌더링을 확인. DB·카메라·모델 미시작 |
| 등록 --ui-smoke | 최초 종료 재진입 예외 발견 후 수정. 최종 exit 0, 설정 창 2회 열기/닫기 및 앱 종료 |

StartupChecks 최초 sandbox 실행의 DPAPI 실패는 실제 Windows 사용자 컨텍스트에서 재검증했다. 해당 검사 복원 중 NuGet 취약점 서비스 접근 불가 NU1900도 관찰됐다. 암호화 런타임 검사는 통과했지만 취약점 온라인 조회가 완료됐다는 의미는 아니다.

## 현장 확인 필요

- 운영 PostgreSQL에서 최초 연결 → 직원 자동 조회/수정, 연결 해제 시 기존 창 종료 확인.
- 저장 선택 후 앱 재시작 → DB/TCP 자동 시작, 저장 해제 후 다음 실행에서 미연결 확인.
- TCP 수동 중지 → DB 재조회에도 중지 유지, 포트 점유 시 실패 표시 및 재시도.
- 다른 PC에서 최초 페어링·저장 코드 자동 연결, 서버 재시작·방화벽·TLS 확인.
- 실제 카메라·AI·얼굴 식별·등록 저장·녹화/재생. 정확도·지연·LAN 성능은 이번에 측정하지 않았다.

UI 미리보기 통과를 운영 DB나 실제 두 PC 통합 시험 통과로 해석하지 않는다.
