- 기본 AI 작업 방식을 Python 내부의 전용 스레드로 바꾸고 동일한 실제 C# 클라이언트 통합 검사를 재실행: 영상/분석 수신, 정면 보정, 5방향 기준 불러오기, 비교, 종료 통과.

- Linux의 테스트 영상과 실제 AI 모델을 사용한 결과다. Windows의 기존 준비 중 증상 해결 여부, Conda DLL 경로 보완 효과 및 WPF 화면은 아직 현장 확인 전이다.

- Python 계산·프레임 유효기간·비동기 작업·얼굴 기준 검증 및 불러오기/내보내기 테스트 10개 통과.
- 실제 Shared/AiClient.cs가 Python wpf_bridge.py를 실행하고 JPEG 영상, 얼굴 분석 JSON, 정면 보정 명령 결과를 받는 통합 테스트 통과.
- 실제 AI 모델로 5방향 기준을 불러오고 비교 결과를 계산하는 통합 테스트 통과. 테스트 카메라는 고정 이미지로 대체했으며 정확도 평가를 뜻하지 않음.
- Python 종료 명령과 자식 프로세스 정리 테스트 통과.

## Windows PC에서 확인할 항목

개발 검증은 Linux에서 실행했다. 아래 항목은 실제 Windows 환경에서 아직 확인하지 않았다.

1. WPF 화면 표시 및 실제 USB 카메라 영상 수신.
2. Camera 1/2 장치 번호 확인, 두 카메라 동시 사용.
3. 등록 앱의 5방향 촬영 완료 → 인증 앱으로 임시 기준 전달 → 인증 화면에서 5/5 확인.
4. 인증 앱 정면 보정 후 비교 시작, 본인/다른 사람/여러 얼굴/얼굴 이탈 시 표시 확인.
5. 앱 종료 후 카메라와 Python 프로세스가 해제되는지 확인.
6. 등록 화면을 두 번째 모니터로 옮겨 최대화하여 사용.

두 앱 간 Named Pipe의 메시지 형식·특징 유효성 검사는 통과했다. 운영체제 전송 테스트는 Linux 환경이 Unix 소켓 생성을 허용하지 않아 실행하지 못했다. Windows Named Pipe의 실제 전달은 위 3번에서 확인해야 한다. C#↔Python 통합 테스트의 특징 불러오기는 이 전송을 거치지 않고 직접 실행했다.

## 이번 묶음의 범위

- 얼굴 특징은 메모리에서만 유지한다. 앱 종료 후 다시 등록해야 한다.
- 출입 권한 판정, TCP 서버 연결, 직원 DB와 얼굴 특징 연결 및 저장은 다음 단계다.
- 비교 결과는 본인 일치 후보이며 출입 승인 결과가 아니다.
- ArcFace 가중치·개인 얼굴 사진·DB 비밀번호는 묶음에 포함하지 않는다. 이미 설치한 Python 가상환경과 모델 캐시를 사용한다.

실행 순서는 루트 README.md를 따른다. 서버의 기존 직원 CRUD를 사용하기 위해 SQL을 다시 실행할 필요는 없다.
