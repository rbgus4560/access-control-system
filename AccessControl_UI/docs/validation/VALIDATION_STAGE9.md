# 9단계 서버 권한 판정과 DB 이벤트 기록 — 2026-10-18

## 내부 검증

- .NET SDK 8.0.426으로 세 WPF 프로젝트 빌드 성공
- 네트워크·정책 검사: NetworkChecks/NetworkChecks.csproj
- 32개 권한 플래그 조합에서 얼굴 일치·직원 활성·등록 활성·출입 허용·장치 허용이 모두 참일 때만 GRANTED
- 얼굴 이탈·여러 얼굴·비교 꺼짐·이전 명령·오래된 분석의 비교 결과 숨김 검사
- 송신 시각 누락·과거 지연·미래 시각으로 현재 분석을 가장하지 못하도록 시간 검사
- 같은 인증 시도 유지, 짧은 품질 저하 유지, 2초 중단 후 새 시도 발급 검사
- 동일 이벤트 입력의 ID 유지, 거부 및 권한 변경 버전의 ID 분리 검사
- 클라이언트가 보낸 허가 판정과 DB 기록 정보 없는 GRANTED 응답 거절
- 실제 루프백 TCP ACK, 서버 중지·재시작 재접속, 손상·불완전 프레임 처리, 정책 콜백 응답 전달 검사
- 저장 완료 GRANTED 응답의 이벤트 ID·거리·한글 신원 데이터 직렬화 왕복 검사
- FaceChecks의 5방향 특징·요청 ID·등록 ID·한글 및 DB 기준 발급 정보 보존 검사

TCP 정책 응답 전달 검사는 테스트용 정책 콜백을 사용한다. 위 검사만으로 실제 PostgreSQL의 권한 조회·행 잠금·이벤트 INSERT를 검증했다고 주장하지 않는다.

## 사용자 PC에서 확인할 항목

1. 기존 DB 얼굴을 재촬영 없이 불러오기
2. 얼굴 일치 + 출입 권한 해제: DENIED / ACCESS_DISABLED 및 실제 DB 행
3. 권한 허용 후 GRANTED / ACCESS_ALLOWED 및 실제 DB 행
4. 권한 재해제·재허용 시 즉시 다음 응답에 반영되고 새 변경 기록 생성
5. 같은 얼굴 유지 중 DB 기록이 매초 증가하지 않음
6. 타인 불일치 시 NO_MATCH 및 person_id/enrollment_id NULL
7. 얼굴 이탈·다중 얼굴·비교 중지·분석 지연에서 이전 허가 숨김
8. TCP 재접속 중 동일 시도의 중복 행 없음
9. DB 미연결·장애에서는 허가 응답 없음
10. 서버 종료·재시작 후 DB 출입 이력 재조회

## 아직 구현하지 않은 범위

선택 직원 한 명의 얼굴 기준을 사용한다. 여러 직원 자동 검색, 실제 출입문 구동, 위조 얼굴 방지, 영상 전송·녹화·타임라인·클립 추출은 별도 구현이 필요하다. 이번 버전 준비를 9단계의 사용자 PC 최종 검증 완료로 해석하지 않는다.
