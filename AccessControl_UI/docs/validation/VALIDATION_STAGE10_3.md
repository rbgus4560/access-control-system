# 10-3단계 타임라인·선택 시각 재생 10.3 — 2026-10-18

## 구현

- 인증 앱 하단에서 날짜별 완료 녹화 구간 조회. 기존 10.2가 저장한 MP4와 JSON을 사용하며 새 촬영·DDL·모델 설치 불필요.
- 24시간 전체 보기, 선택 위치 중심 1시간·10분 확대. 파랑은 읽기 가능한 READY 파일 구간이며 빈 곳은 재생 가능한 녹화가 없는 구간.
- 구간 목록 선택 후 '선택 구간 재생', HH:mm:ss(.fff) 입력 후 '시각 재생', 타임라인 클릭으로 재생.
- WPF MediaElement로 MP4를 선택 위치에서 재생. 일시정지·재생·다음 구간·LIVE 복귀 제공.
- 60초 구간 분할 시 0.25초 이내의 짧은 간격은 다음 파일로 자동 연결. 실제 공백에서는 멈추며 다음 구간 버튼으로 이동한다. 마지막 파일에서 끝나면 반복 재생하지 않는다.
- PLAYBACK 제목에 현재 재생 시각을 표시. 재생 화면에서는 현재 얼굴 인증 허가 표시를 숨기고 현재 판정은 서버에서 확인하도록 안내한다.
- 재생 중에도 기존 AI 프로세스·실시간 카메라·구간 녹화·서버 영상 전송은 유지한다. LIVE 복귀는 재생 파일을 닫고 기존 인증 화면을 다시 표시한다.
- 이번 타임라인은 단일 PC의 로컬 파일 목록 기준이다. 서버 DB 동기화와 독립적이므로 DB 미연결 중 저장한 READY 구간도 볼 수 있다. RECORDING/FAILED 및 누락·크기 불일치 파일은 재생 목록에 넣지 않는다.
- 날짜·시각은 Windows 로컬 시간이며 현재 시연은 한국 표준시다. UTC 날짜 폴더를 로컬 날짜 구간으로 변환해 조회한다. 파일 경로·크기·완료 상태 검증은 10.2 규칙을 따른다.

## 내부 검증

- .NET 8.0.426 MSBuild로 세 WPF 프로젝트 빌드 성공.
- FaceChecks: 기존 얼굴·녹화 정보 계약과 함께 타임라인 시작·끝 경계, 구간 내부 선택, 실제 빈 구간, 4ms 분할 간격, 다음 구간·마지막 구간, 밀리초 시각 입력과 잘못된 시각 거절 검사 통과.
- NetworkChecks: 기존 얼굴 상태·권한 32개 조합·실제 상태 TCP·영상 TCP·재접속·영상 미연결 중 인증 응답 유지 검사 통과.
- 검사 콘솔은 같은 SDK의 Roslyn과 .NET 8 참조 어셈블리로 컴파일하여 실행했다.
- Windows WPF 실행·MediaElement 코덱·실제 선택 위치 재생은 이 Linux 환경에서 확인할 수 없다. 사용자 PC 확인 전에는 실제 재생 성공이나 영상 시각 정합성까지 검증했다고 주장하지 않는다.

## 사용자 확인

1. 기존 앱 모두 종료, 최신 ZIP 덮어쓰기, Start_Stage10.cmd 실행. 창 제목 10.3 확인.
2. 인증 앱 하단의 날짜를 2026-10-18로 선택하고 '구간 조회'. 카메라를 새로 열 필요 없이 기존 완료 구간이 나와야 한다.
3. 목록에서 15:52:41.003~15:53:41.003 또는 다른 READY 구간 선택. '선택 구간 재생'으로 앱 내부 PLAYBACK 영상과 증가하는 녹화 시각 확인.
4. '일시정지'와 '재생' 확인. 시각 칸에 예를 들어 15:53:00을 넣고 '시각 재생'하여 구간 중간 위치에서 재생되는지 확인.
5. '10분' 또는 '1시간' 확대 후 파란 구간 클릭. 녹화가 없는 시각 선택 시 '녹화 없음' 표시와 이전 영상 해제 확인.
6. 첫 60초 파일 끝에서 다음 16.4초 파일로 자동 연결 확인. 마지막 구간 끝에서는 완료 안내 확인.
7. LIVE 또는 LIVE 복귀 버튼으로 실시간 인증 화면 복귀. 카메라를 연결했다면 재생 중에도 서버 영상·인증·녹화가 유지되는지 확인.

Windows 영상 재생 실패 안내가 나오면 해당 MP4의 기본 플레이어 재생 여부와 화면 오류를 확인한다. 기본 플레이어에서 재생됐다는 사실만으로 MediaElement에서의 재생 성공을 대신하지 않는다.
