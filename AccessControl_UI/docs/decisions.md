# 설계와 리팩토링 결정

## 실행 CMD와 진단 CMD 분리

Start_Net10과 Start_Stage7~10은 파일 해시가 같은 서버/클라이언트 선택 래퍼라 삭제했다. 현재 역할별 시작점은 Start_Server와 Start_Client로 명확히 유지한다. 등록 UI와 보관 정책 검사 CMD는 서로 다른 기능이 있어 scripts/checks로 이동하고 프로젝트 루트를 자신의 위치에서 계산하도록 보정했다. 과거 문서의 명령명은 역사적 근거로 보존하고 guides/COMMANDS.md에 현재 대체 방법을 기록한다.

## 문서 위치와 원문 보존

단계별 검증은 docs/validation, 사용 안내는 docs/guides, 장애 수정 원문은 docs/fixes, 버전 이력은 docs/history로 나눴다. 프로젝트 루트에는 README와 CHANGELOG만 남겼다. 모델 출처·라이선스와 각 실행 모듈의 README는 관련 파일 옆에 유지한다. 기존 Word 보고서는 개발 과정의 시점별 보고서이므로 다시 생성하지 않았으며, 현재 파일 위치는 docs/README.md를 기준으로 찾는다. 이동 시 원문과 검증 수준을 보존하고 Markdown 상대 링크를 보정했다.

## 독립 도구와 통합본 유지

초기 독립 도구는 5방향·단일인 비교 실험이고 통합본은 WPF·서버·전체 직원 검색·녹화를 포함한다. 파일명 유사성만으로 통합하면 실험 재현과 별도 실행이 깨질 수 있어 이번에는 두 폴더를 유지했다. 공용 패키지 분리는 배포·의존성 전략을 결정한 뒤 검토한다.

## 반복 입력 정규화 제거

한 번의 참조 비교에서 입력은 같으므로 입력 정규화만 호출당 한 번 수행한다. 참조 정규화·딕셔너리 순서·코사인 거리와 기존 오류 차단은 유지한다. 샘플 전체 행렬화를 추가하면 계산 순서 변화가 생길 수 있어 이번에는 적용하지 않았다. 속도 향상률을 측정한 것은 아니다.

## 생성물 삭제와 실행 데이터 보존

재생성 가능한 obj·비실행 bin·Python 캐시만 삭제했다. 실행 중 앱의 bin, 모델·캐시, 이력·검사 자료는 사용 근거가 있어 보존했다. 원본 영상과 실제 DB는 정리 대상에 포함하지 않았다.

## 검증 환경과 실행 중 프로세스

대상 Python 3.11 환경으로 검증하고 다른 환경의 API 부재를 제품 코드 결함으로 오판하지 않았다. 실행 중 EXE 잠금은 앱 강제 종료 대신 별도 출력 경로 빌드로 확인했다.

## 2026-10-22 · 연결 및 종료 처리

- 직원 창은 별도 비밀번호 입력 대신 서버가 검증한 endpoint/password와 세션 유효성 함수를 전달받는다. DB 연결 교체·해제 시 창을 닫아 이전 자격 증명으로 편집하는 일을 막는다. 영구 열린 DB 소켓 하나를 공유한다는 의미는 아니다.
- 자동 시작은 평문 설정 대신 Windows DPAPI CurrentUser를 사용하고 저장은 명시적 선택으로 제한한다. TCP의 수동 중지 의사는 DB 재조회에서도 유지한다. 클라이언트는 기존 페어링 보안을 유지한다.
- 자원 해제가 동기 완료되어도 Closing 이벤트 안에서 Close를 재호출하지 않도록 Dispatcher에 다음 종료를 예약한다. 등록 진단은 Closed 후 종료 코드를 반환한다.
- 화면 검증은 실제 WPF 렌더링으로 수행하되 미리보기에서 운영 통신·카메라·저장 설정을 건드리지 않는다. 자세한 범위는 12.4 검증 기록 참조.
