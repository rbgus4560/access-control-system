# 안내형 아래 방향 수집 개선 · 2026-10-22

사용자 보고: 얼굴은 검출되지만 아래 방향 수집이 대부분 진행되지 않는다.

## 수정과 확인

정면 복귀와 첫 각도/다른 각도 수집의 대기 시간을 구분하여 5Hz 분석 중 얕은 시점을 놓치는 합성 경로를 수정했다. 화면에 후보가 없는지, 첫 후보가 확보됐는지와 다음 움직임을 안내한다. 품질·동일인 판정·필요한 두 각도 기준은 유지한다. 최초 회귀 검사에서 미완료를 재현했고 수정 후 완료를 확인했다. 실제 사용자의 카메라 입력을 재현한 정확도 측정은 아니다.

Python 3.11 환경의 최종 51개 전체 검사(신규 2개 포함)가 통과했다. 서버·등록 앱 빌드는 통과했고 인증 앱은 실행 중 EXE 잠금으로 기본 출력 빌드가 실패했다(MSB3027/MSB3021). 앱을 강제 종료하지 않고 build-check/FaceRecognition 별도 경로에서 경고·오류 0개로 빌드했다. 별도 출력 생성물은 Git에서 제외한다.

## 적용과 재시험

열려 있는 등록 앱과 인증 앱을 정상 종료하고 서버 메뉴에서 등록 앱을 다시 연다. 새 안내가 안 보이면 등록 앱도 다시 빌드한다: `dotnet build FaceEnrollment/FaceEnrollment.csproj` (AccessControl_UI에서 실행). 인증 앱은 정상 종료 뒤 Start_Client.cmd로 재빌드한다. 서버도 필요한 시점에 정상 재시작한다.

정면부터 등록을 다시 시작한다. 아래 단계에서는 턱을 조금씩 내려 첫 샘플을 얻고, 안내가 정면 쪽 복귀를 요청하면 조금 돌아오며 두 번째 각도를 보여 준다. 깊게 숙인 상태로 계속 버티거나 더 과도하게 숙일 필요는 없다. 실제 해결 여부는 이 재시험으로 확인해야 한다.

계속 멈추면 안내 문구와 얼굴 검출 상태를 확인한다. 기존 얼굴 기준과 모델 캐시·DB는 삭제할 필요가 없다. 기존 등록을 새 방식으로 자동 변환하지 않으며 새 등록은 9개가 완성된 뒤 DB에 저장한다.
