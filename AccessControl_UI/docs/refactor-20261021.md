# 2026년 10월 21일 리팩토링 기록

## 변경 이유와 범위

두 프로젝트의 독립 실행 가능성을 보존하면서 반복 계산과 반복 제어 코드를 정리했다. 모델·임계값·DB 스키마·통신 계약은 변경하지 않았다.

- FaceAI/face_logic.py와 독립 도구 face_logic.py: reference_distances로 입력 특징의 반복 정규화 제거. 각 참조의 검증과 삽입 순서 보존.
- FaceRecognition/GallerySynchronizer.cs: 연결 세대 확인·상태 표시 함수 추출과 폴링 간격 상수화.
- 두 폴더 .gitignore: 빌드·Python 캐시·로컬 모델 캐시·실행 데이터 제외.
- 문서: 두 프로젝트의 개발 흐름과 트러블슈팅, 변경·삭제·검증 근거 정리, Word 보고서 작성.

## 삭제와 보존

삭제한 생성물은 134개 파일, 11070282바이트다. 8개 대상 디렉터리의 절대 경로를 프로젝트 내부로 확인한 뒤 제거했다. 파일 단위 임의 소스 삭제는 하지 않았다.

서버와 인증 앱이 실행 중이므로 해당 bin은 보존했다. 등록 앱과 TwoPcChecks의 비실행 bin, 빌드 obj, 두 프로젝트의 Python 캐시를 제거했다. models·model_cache는 모델 재다운로드와 실행에 사용하므로 삭제하지 않았고 이력 문서·테스트·옛 실행 파일의 소스도 보존했다.

바탕화면 AccessControl_Refactor_20261021에는 변경 전 소스 3개, 삭제 내역 cleanup-manifest.json, 전후 수치 비교 스크립트가 있다. 이 폴더는 배포 소스가 아닌 로컬 검토 자료다.

## 검증과 실행

access_face_ai Python 3.11.17에서 통합본 49개·독립 도구 9개 검사 통과. 각 프로젝트의 고정 난수 500개와 동점 선택이 변경 전과 일치. C# 갤러리 동기화·관측 정책 2개 묶음 PASS. 서버·등록 WPF 빌드 통과, 인증 앱은 EXE 잠금 때문에 별도 출력 경로 빌드 통과.

초기 Python 환경 오선택과 실행 중 EXE 빌드 실패는 troubleshooting.md의 TS-17~18에 기록했다. 카메라·모델·운영 DB·LAN·실제 UI를 새로 검증한 결과는 아니다.

현재 앱은 기존 프로세스이므로 리팩토링 반영은 앱을 정상 종료하고 Start_Server.cmd·Start_Client.cmd로 재빌드·실행할 때 이루어진다. obj를 제거했으므로 다음 실행에서 의존성 복원이 다시 수행될 수 있다. 이번 작업은 실제 DB나 녹화 원본을 삭제하지 않았다.
