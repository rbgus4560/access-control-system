# 12.2.4 클라이언트 자동 보정·비교

12.2.3의 UI·녹화 동기화·클립 수정 사항을 모두 포함한다.

## 실행

1. 앱을 모두 종료하고 새 폴더에 압축을 푼다. 기존 정상 폴더와 DB·AppData는 보존한다.
2. 새 `Start_Server.cmd`와 `Start_Client.cmd`로 실행한다. 창 제목은 12.2.4다.
3. 클라이언트의 `클라이언트 설정 > 카메라·AI`에서 **AI 폴더를 이번 파일의 FaceAI로 변경**한다. 기존 Python·모델 캐시 경로는 유지할 수 있다. 이전 FaceAI를 가리키면 자동 시작이 적용되지 않는다.
4. 서버 연결 후 `인증 기준 선택`에서 직원 얼굴을 불러온다.
5. `카메라·AI 연결`을 누르고 정면을 바라본 채 잠시 멈춘다. AI 준비 후 정면에 가까운 자세가 안정되면 자동 보정하고 얼굴 비교를 시작한다. 카메라 연결 전후 어느 때든 기준 얼굴을 불러올 수 있다.

## 동작

- 초기 정면 근접 조건: 절대 pitch 20도, yaw 18도, roll 12도 이내. 자세 변화 4도 이내로, 최소 3개의 독립 분석 결과가 0.8초 이상 이어져야 한다. 분석 간격이 1.5초를 넘거나 자세가 크게 바뀌면 안정화 시간을 다시 센다. 실제 대기 시간은 AI 처리 속도에 따라 늘어난다.
- 유효한 한 얼굴과 새 분석 결과만 보정에 사용한다. 얼굴 없음·다중 얼굴·AI 오류는 안정화 누적을 끊는다. 정면 근접은 모델의 자세 추정이며, 신원 확인이나 실제 생체 여부 증명이 아니다.
- 기준 얼굴이 없으면 직원 선택을 안내하며 인증 후보를 만들지 않는다. 직원 불러오기는 선택 직원 1:1 비교 방식으로 유지한다.
- `얼굴 비교 중지`를 누르면 자동으로 다시 켜지지 않는다. `얼굴 비교 시작`으로 재개할 수 있다. 수동 중지 중 정면 재보정도 비교를 자동 재개하지 않는다.
- 유효한 새 직원 기준을 불러오거나 카메라를 다시 연결하면 자동 시작을 다시 준비한다. 잘못된 기준을 수신하면 이전 얼굴 비교를 자동 재개하지 않는다.
- 자동 보정이 오래 걸리면 실제 정면·조명·카메라 높이를 확인한다. 필요하면 `정면 재보정`으로 현재 자세를 수동 보정할 수 있다.
- 비교 임계값 0.450, 여러 얼굴/오래된 결과 차단, 서버 최종 출입 권한 판정은 유지한다. 등록 앱의 수동/회전 등록 흐름은 그대로다.

## 확인

- 자동 시작·기준 없음·측면 거부·움직임/간격 초기화·수동 중지 유지·새 기준 적용·초기화·잘못된 기준·타인 불일치·다중 얼굴·AI 오류를 모델 대역으로 검증했다.
- Windows USB 카메라 및 실제 얼굴 모델의 자동 정면 보정은 사용자 PC에서 확인해야 한다. AI 준비 후에도 보정 대기가 계속되면 화면의 상태 문구와 진단을 확인한다.

검증 결과: Python 검사 44개 통과, WPF 세 앱 교차 빌드 통과. 실제 얼굴 모델·USB 카메라 자동 보정은 미실행.
