# 8단계 직원·얼굴 특징 DB 연결 검증 — 2026-10-18

## 기존 사용자 PC 확인

7.0 TCP 연결 및 서버 재시작 후 자동 재접속을 사용자 확인했다. 기존 PostgreSQL access_control_system 조회 성공과 ENROLLMENT-01/RECOGNITION-01 및 CAM-01/CAM-02 목록을 사용자 화면에서 확인했다. 이는 새 얼굴 특징 저장까지 확인했다는 의미가 아니다.

## 개발 환경에서 확인

- .NET SDK 8.0.426에서 WPF 세 프로젝트 빌드 성공
- 5방향 512차원 및 모델 버전 검증, 방향 누락·잘못된 차원·0벡터·숫자가 아닌 값 거절
- DB 요청 ID/직원 ID 및 한글 응답 보존, 특징 JSON 직렬화 왕복
- 요청 128000바이트, 응답 512000바이트 상한 및 잘린 길이 헤더 거절
- 테스트 프로젝트: FaceChecks/FaceChecks.csproj

## Windows 사용자 PC에서 확인해야 하는 항목

1. 새 8.0 서버 DB 조회 및 기존 관리자 선택 또는 신규 관리자 생성
2. 등록 앱에서 서버를 통한 직원 조회
3. 선택 직원 5방향 촬영 및 DB 저장 성공
4. 읽기 SQL에서 활성 묶음의 특징 5개 및 버전 확인
5. 등록 앱 카메라 종료 후 인증 앱에서 DB 기준 불러오기
6. AI 기준 5/5와 본인·타인·얼굴 이탈·다중 얼굴 비교 상태 수신
7. 인증 앱을 종료하고 다시 열어 재촬영 없이 같은 DB 기준 복원
8. 기존 등록 교체 시 과거 묶음 비활성 및 새 묶음만 활성 유지

Linux 개발 환경에서는 실제 Windows DPAPI와 사용자 PostgreSQL에 새 기능을 실행하지 않았다. 따라서 암호화 저장·트랜잭션과 재시작 복원은 위 사용자 PC 검사 전까지 미검증이다. 기존 DB를 초기화하지 않으며 새 DDL은 필요하지 않다.

## 코드상 처리 정책

서버만 DB 접속 정보를 보관한다. 같은 사용자 전용 로컬 Named Pipe는 DB 요청에 사용하고 TCP는 분석 상태에 사용한다. SQL 파라미터 바인딩, 직원 행 잠금, 등록 버전 비교, 5개 특징 저장 및 활성화의 단일 트랜잭션을 사용한다. DB 비활성 직원과 비활성 관리자의 새 등록은 거절한다. 불러오기는 활성 직원·등록과 일치하는 전처리 버전만 허용한다.

현재 비교 범위는 선택 직원 1명의 5방향 기준이다. 출입 권한과 access_events DB 저장은 아직 연결하지 않았다. 원본 얼굴 사진 저장·전체 직원 자동 검색은 이번 변경에 포함하지 않았다.
