# 10-5 MP4 클립 추출 10.5 — 2026-10-18

## 구현과 사용

1. 기존 앱 종료 후 ZIP 덮어쓰기, Start_Stage10.cmd 실행. 두 앱 10.5 확인.
2. 서버 DB 연결 및 목록 조회. 얼굴 등록 관리자에 기존 활성 관리자를 선택한다. 이 관리자가 클립 추출 담당자로 기록된다.
3. 인증 앱 하단 '클립 추출' 클릭. 날짜 2026-10-18, 시작 15:49:05, 종료 15:49:10으로 첫 확인을 한다. 해당 범위는 기존 READY 녹화 안에 있다.
4. 현재 출입 기록 연결을 선택했다면 해당 이벤트 시각이 추출 범위 안에 있어야 한다. 필요 없으면 연결을 해제한다.
5. MP4 클립 추출. 완료 메시지의 실제 출력 길이와 파일 크기, DB 기록 완료 여부 확인.
6. 완료 파일 재생 또는 클립 폴더 열기. 약 5초짜리 MP4가 실제로 재생되는지 확인.

같은 날짜의 시작·종료 시각 HH:mm:ss(.fff), 최대 5분을 지원한다. 추가 카메라·AI 모델·ffmpeg.exe 설치 없이 기존 Python 환경의 OpenCV를 사용한다. 원본 MP4는 유지하며 음성은 포함하지 않는다.

## 파일·시간 처리

- 로컬 READY 녹화의 범위를 확인하고 필요한 프레임만 읽어 mp4v 10fps로 새 MP4에 기록한다. 여러 원본 파일을 하나로 합칠 수 있다.
- 일반적인 60초 분할 간격(0.25초 이하)만 허용한다. 실제 공백·시작/끝 부분 누락·해상도 변경·지나치게 많은 구간은 거절한다.
- 프레임 단위 선택이므로 개별 경계는 0.1초 단위로 맞춘다. 내부 분할 간격의 누적 오차를 포함해 출력 길이와 요청 길이가 1초 넘게 다르면 추출을 거절한다. 정확한 출력 길이는 완료 메시지에 표시한다.
- 소스 프레임을 순서대로 건너뛰므로 키프레임 기반 탐색 오차를 피한다. 완료 후 첫 프레임·프레임 수 확인, 실제 크기와 SHA256 계산. 모든 프레임 무결성 검사를 했다는 뜻은 아니다.
- 출력 위치: `%LOCALAPPDATA%\AccessControlSystem\clips\구간ID.mp4`.
- 같은 이름 JSON은 완료 상태·DB 재시도용 정보이며 .job.json은 추출 계획이다. 두 정보 파일도 함께 보관한다. 자동 클립 삭제는 없다.

## DB·실패 처리

- 기존 exported_clips 사용. 새 DDL 불필요. 시작 시 활성 관리자·카메라·선택 이벤트 범위를 검증해 EXPORTING 생성.
- 완료 시 READY와 실제 크기·SHA256·완료시각 기록. 서버도 파일 크기·해시·정보 파일을 확인한다. 같은 클립ID 결과 재전송은 중복 행을 만들지 않는다.
- 일반 실패·사용자 창 닫기 취소는 FAILED 정보 저장 및 DB 반영을 시도한다. 취소한 Python 프로세스는 종료한다. 강제 프로세스 종료·PC 전원 차단으로 남은 EXPORTING 구간을 자동 복구하는 기능은 아직 없다.
- MP4 생성 후 DB 연결이 끊기면 파일과 완료 정보를 보관하며 인증 앱이 3초 동기화 주기에서 자동 재시도한다. 기존 추출 시작 행이 있는 원래 DB에 반영한다.
- 새 클립 시작에는 서버 DB·활성 관리자 선택이 필요하다. 완료 후 동기화 대기인 경우를 DB 완료로 표시하지 않는다.
- 출력 전 여유 공간 20GB 기준을 확인한다. 추출은 최대 2분 제한으로 실행하며 UI·카메라·인증은 별도 작업으로 유지한다.
- DB 확인: Database/11_verify_exported_clips.sql. 파일 내용은 DB에 넣지 않는다.

- 실제 사용자 Windows의 conda DLL·코덱과 DB 클립 INSERT/UPDATE, 5초 MP4 재생은 적용 후 확인해야 한다. 개발 환경 코덱 검사를 사용자 PC 검증으로 대신하지 않는다.
